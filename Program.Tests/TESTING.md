# Проверки перед выпуском

Политика журналов сборок проверяется отдельно от интерфейса: `python -m unittest discover -s tools/PackData/Logging -p test_logging_policy.py -v`. Эти проверки воспроизводят подготовку и последующее авторское обновление исходников, сохранение чужих настроек, отказ при конфликте и проверку ownership. Нативные вызывающие методы шести профилей и настоящие фильтры Log4j трёх версий задокументированы в `tools/PackData/Logging/Verification`; это не игровой прогон.

Обязательный профиль `Release` содержит **607 случая по 370 точным методам**. Он проверяет сохранность данных, установку и откат, источники и запуск, Steam и профили игроков, библиотеку и переносимый runtime. В него входят запуск нативной игры и передача мира в формате Minecraft 26.3, доставка уведомлений SDL и нативному дочернему процессу. Подробные исторические комбинации и дополнительные матрицы остаются в `Full` и `AdaptersFull`.

Порог защиты от потерянного фильтра составляет 607 случая. Каждый выбранный метод должен присутствовать в TRX, все его запущенные случаи обязаны пройти без пропусков. Профиль использует точные имена методов и отклоняет запуск полного набора.

К компактной базе main из 473 случаев добавлены 45 критичных случаев Legacy Fabric: явная Java и прежние descriptor hashes, официальный mappings/LWJGL profile, происхождение Steam-порта и V3 при холодном офлайн-запуске, запрет потери legacy-покрытия при старом кеше/индексе, стабильные имена и профили при смене ника/хоста, безопасные пути и junction, неизменный контекст личности запуска и личная статистика. Дополнительные матрицы остаются в Full/AdaptersFull. Эти проверки не подменяют client/world/Steam-приёмку сборки; её воспроизводимый стенд и сценарный host находятся в [репозитории Better Than Wolves](https://github.com/MarkZamore/Better-Than-Wolves/tree/main/tools/runtime-qa), формат профилей в `tools/LEGACY-PLAYER-PROFILES.md`.

```powershell
$env:JAVA_HOME = 'C:\Tools\jdk-25.0.2'
.\Program.Tests\Test-Launcher.ps1 -Profile Release
```

Нужны Windows, .NET 10 и JDK. Если JDK недоступен, используйте `-SkipPortableIdentityAdapter`; это не исключает тесты. Скрипт сначала собирает настоящий адаптер и Debug-сборку лаунчера, затем тесты и небольшой тестовый процесс без повторной сборки зависимости. Флаги CI `-NoRestore` предполагают предварительный restore всех трёх проектов.

Обычная сборка тестового проекта также собирает технический host через ссылку проекта, поэтому свежий checkout поддерживает прямой `dotnet test` и профиль `Full` без ручной подготовки. Проверка рендера запускает только технический host с настоящим runtimeconfig лаунчера. В конфигурации `Release` она копирует автономный CLR, WPF и deps сборки в собственную временную папку; конфигурацию не переписывает и удаляет копию после завершения процесса. `-Configuration Release` использует этот же путь.

Не заменяйте эту команду одним `dotnet test --settings Release.runsettings`: обязательная проверка обновления требует подготовленного тестового процесса и изолированной папки. Скрипт создаёт их автоматически, отклоняет пропуски и проверяет результаты. Обычная команда `dotnet test Program.Tests -c Debug` по-прежнему запускает полную регрессию, которая больше не обязательна для каждого выпуска.

Добавлены семь обязательных случаев `PackPlayFreshManifestTests`: новый манифест при «Играть» без перезапуска для каталога и пользовательского алиаса, удаление старого управляемого JAR, один снимок для расчёта/метаданных/применения при следующей публикации, офлайн-сохранение установленного состава, отмена HTTP и отказ при неизвестной обязательной возможности и предел 8 МиБ для chunked-манифеста без Content-Length. Проверки карточек по-прежнему используют стартовый снимок, а игровой состав проверяется перед запуском.

Две проверки IdentityAdapterChunkPacingTests входят в Release: новые aliases включаются только при полной цепочке игрового соединения, а настоящая очередь чанков приостанавливается перед извлечением элемента и возобновляется после освобождения канала. JVM-fixture проверяет нулевой RTT, смену writable внутри одной порции, FIFO, отмену и переподключение, локального игрока, memory connection и отсутствие необязательных маппингов. Дальность и прежний предел памяти очереди сохраняются; это проверка механизма, а не успешного подключения двух игроков через Steam. После изменения маппингов preflight требует свежих aliases из подготовки новым кодом.

## Выпуск сборки и выпуск лаунчера

Program.Tests собирается отдельно в Minecraft.Tests.dll и не входит в поставляемый LANMinecraft.exe. Общие проверки лаунчера и Minecraft-версий/загрузчиков остаются универсальными в этом репозитории. Проверки конкретных JAR/SHA, модов, конфигов, квестов и приёмки мира принадлежат репозиторию соответствующей сборки и используют её manifest/lock как источник данных.

Публикация одних данных сборки или каталога не запускает Test-Launcher, не выпускает новый EXE и не прогоняет все сборки. При изменении реализации лаунчера или общего адаптера выполняются компактный Release и адресные проверки изменённого механизма. Найденные 767 случаев при подготовке Better Than Wolves были общим Release-прогоном изменявшегося checkout лаунчера, а не восемью отдельными наборами. Их не нужно копировать в репозитории сборок.

Миграция сборок дополнительно проверяет фактический SHA при прежних размере и времени, исторические хеши старой установки, прерванное применение и повторную попытку, сохранённую ownership, запрет запуска неполного обновления и исключение неизвестных JAR из активного состава. Точный текущий транспорт сохраняется при повторной подготовке экземпляра. Ложная неподтверждённая подсказка процесса Steam не отменяет успешно инициализированный API с подтверждённым входом; закрытие клиента, выход, смена аккаунта и таймаут переподключения проверяются отдельно.

Точный список методов находится в `Release.runsettings`. Теории раскрываются в самостоятельные случаи: например, все десять проверок опасных путей манифеста остаются обязательными. Существующий связный сценарий обновления запускает производственный PowerShell-помощник и проверяет реальные замену, перезапуск и сохранность старого EXE при ошибке. Данные, сеть загрузок и процесс-получатель обновления изолированы; Steam, установленные сборки и личные миры не требуются.


CI запускает тот же короткий профиль при выпуске EXE. Валидатор отклоняет пустой фильтр, повторённые или неизвестные селекторы, ошибки, пропуски, несогласованные счётчики и неожиданные методы. При сокращении профиля по просьбе пользователя новый локальный прогон не выполнялся: все 473 случая сопоставлены по testId и точным методам с завершённым успешным прогоном из 760 случаев (440 методов). Это проверка покрытия имеющихся результатов, не новый запуск тестов. Подробный список хранится в Release.runsettings.

В CI тесты заканчиваются до запуска `Publish.ps1`: Debug и Release используют общие Java JAR и файлы состояния в `Program/Build`. Параллельная сборка этих этапов вызывает конфликт записи. Проверка выполняет настоящий блок workflow с подставными сборщиками и проверяет порядок, а также остановку при ошибке тестов или публикации. Загрузка предыдущих версий и создание независимых дельт остаются параллельными.

## Дополнительные профили

После изменений подключения Steam адресно запускать `SteamBootstrapTests`, `SteamRecoveryPolicyTests`, `SteamIdentityServiceTests` и `SteamGatedControlsTests`. Сценарий автоматических проверок проходит отсутствие клиента, запуск без аккаунта, вход, выход и вход в другой аккаунт; проверяет новую привязку UUID и отсутствие повторной инициализации готовой сессии. Отдельно проверяются отсутствие кнопки повтора и геометрия строки «Steam: нет подключения». Это проверки с подставным Steam API; настоящий повторный вход в Steam ими не подменяется.

```powershell
# Полная регрессия; аудит с локальными JDK-архивами остаётся явным opt-in.
.\Program.Tests\Test-Launcher.ps1 -Profile Full

# Матрица маппингов/байткода и совместимости загрузчиков.
.\Program.Tests\Test-Launcher.ps1 -Profile Adapters
.\Program.Tests\Test-Launcher.ps1 -Profile AdaptersFull

# Проверки только затронутого модуля.
dotnet test Program.Tests -c Debug --filter FullyQualifiedName~MemorySizingTests
```

При изменениях адаптера используйте профиль `Adapters`; на машине с установленными сборками дополнительно прогоните `Program/IdentityAdapters/Common/Verify-IdentityAdapter.ps1` по свежим алиасам. Изменения геометрии интерфейса проверяются всей группой `WindowCanvasTests` и настоящим рендером согласно `AGENTS.md`. Остальные подробные таблицы совместимости, арифметики, текста, старых миграций и диагностик запускайте по затронутым подсистемам или профилем `Full`.

Результаты сохраняются в игнорируемой папке `Program.Tests/TestResults`. После успешного обязательного прогона временный тестовый процесс и установки удаляются, TRX и краткая сводка остаются. При ошибке сохраняется материал для диагностики. Для уже собранных файлов можно использовать `-NoBuild -HostPath <актуальный PortabilityAuditHost.exe>`; процесс должен быть опубликован с той же текущей зависимостью лаунчера.

Проверку самого валидатора можно выполнить без сборки и запуска тестов: `Test-Launcher.ps1 -ValidateTrx <результат.trx>`. Этот режим использует те же правила отказа, что и обязательный прогон.

## Измерение интерфейса настоящими контролами

`PeerNoticeOverlayTests` проверяет выбор дисплея окна игры или лаунчера, возврат уже
открытых уведомлений к лаунчеру после закрытия игры, недействительный оконный
дескриптор и сохранение фокуса. Нативная проверка использует доступные мониторы;
на ПК с одним дисплеем она не заменяет ручную проверку двух дисплеев с разным DPI.

```powershell
dotnet run --project tools/MeasureLayout -- . current
dotnet run --project tools/MeasureLayout -- . library --library-only
dotnet run --project tools/MeasureLayout -- . six-packs --six-packs
dotnet run --project tools/MeasureLayout -- . grouped-mods --library-only --grouped-mods
dotnet run --project tools/MeasureRemoval
```

`MeasureLayout` — .NET 10/WPF, настоящие `CenteredDropDown`, системные шрифты и renderer лаунчера без запуска Steam и сетевого startup. Полный проход содержит 72 случая: три размера окна, DPI 100/125/150/200%, свёрнутые и раскрытые категории, длинный чат, библиотека, предпросмотр и моды. `--probe` оставляет один минимальный макет лаунчера, `--probe-library` — один макет библиотеки. JSON с геометрией, PNG и контрольные суммы сохраняются в `artifacts/MeasureLayout/<имя>`; снимки проверяются визуально вместе с результатами `WindowCanvasTests`. Полоса прокрутки, вынесенная в правый отступ, включена в снимок без масштабирования остального содержимого.

`MeasureRemoval` отдельно измеряет настоящий диалог удаления при ширине 552/440/280 DIP и DPI 100/163/200%, сохраняя PNG в `artifacts/MeasureRemoval`. Он не вызывает операции удаления сборки. Диалоги дополнительно защищены `DialogLayoutTests`.

Результаты локальных измерений, стендов и промежуточные EXE находятся только в игнорируемом `artifacts/`; повторно используемые исходники инструментов остаются в `tools/`. Устаревшие прототипы startup hooks, отдельных окон уведомлений и отменённого графического backend не заменяют действующие тесты `RenderingStartupTests`, `GameNoticeOverlayServiceTests`, `NoticeOverlayAgentTests` и OpenGL-стенд `tools/NoticeOverlayProbe`.

## Переименование TerraFirma Rebirth

Обязательный Release проверяет перенос той же установленной сборки в `TerraFirma Rebirth 2`: неизменные файлы мира, ID, личные файлы, память, выбранный мир и junction `saves`. Дополнительные `TerraFirmaPackMigrationTests` и `TerraFirmaCatalogRenameTests` проверяют конфликт папок, живую игру/lock, повтор после прерывания, офлайн-кеш и сохранение пользовательских источников. Это проверка миграции данных, а не игровой прогон.

`PackCatalogDisplayNameTests` входит в Release двумя сценариями: установленная и ещё не скачанная сборка. Следующий startup загружает новое название с тем же ID/relativePath через настоящий путь проверки манифеста и архива библиотеки; список запуска обновляется без изменения выбора, памяти, личных файлов и миров.

Авторитетность каталога GitHub проверяют `PackCatalogAuthorityTests`, `KnownPackTests`, `CatalogSourceMarkerTests` и `PackCatalogPlayMembershipTests`: удаления и пустой индекс, отсутствие возврата из seed/маркеров, сохранение файлов и миров, отказ повреждённого индекса, работа офлайн и проверенная смена источника. Состав встроенного снимка сверяется с JSON, а не со списком имён в C#. Старые автоматические маркеры следуют проверенному адресу каталога; явно пользовательские форки сохраняют свой источник.

## Отдельный список дополнений и локальный AI

CatalogPresentationTests проверяет отдельные полный native inventory и отображаемый счётчик выбранных дополнений, аддон скрытого базового мода и заголовок из проверенных метаданных.
Два сценария включены в Release. Подготовка описана в tools/LIBRARY-PRESENTATION.md.

Один связный `PackCatalogTests.FilteredDisplayCountsNeverReplaceThePublishedNativeMemoryCount` проверяет свежий manifest с 9 native mods при 1 показанном корне и 2 вложенных аддонах: счётчик дерева равен 3, сворачивание/группы его не меняют, helpers исключены, scope all учитывает 7 всех content IDs до фильтра при том же показанном дереве; фактическая оценка памяти сохраняет native 9. Восемь случаев `CatalogModGroupTests` входят в Release: optional metadata и полное покрытие корней без повторов, прежние плоские карточки, четыре раздела с обычным деревом модов, независимые ссылки/стрелки и размер стрелки по тексту при 100/200% DPI. Названия разделов и их состав приходят из файлов сборки; библиотечные элементы сохраняют прежний отдельный формат.

LocalAiProvisioningTests проверяет первую подготовку, повторное использование,
восстановление изменённых распакованных файлов, докачку и личные голосовые
настройки. Резерв модели учитывается отдельно от Java PID и не меняет введённый
игроком heap. Подготовка файлов не создаёт и не переписывает конфиги модов,
включая личные голосовые настройки и некорректный пользовательский TOML.
Изменение дескриптора во время подготовки отклоняется до готового результата.
Эти проверки включены в Release. Маленький fixture
не подтверждает фактическую модель или жизненный цикл игрового процесса.

LocalAiRecipeTests проверяет публичную подготовку по закреплённому рецепту самой
сборки. `launcher/local-ai.json` связывает `recipeFile` под `launcher/` и
`recipeSha256`; JSON рецепта задаёт официальный архив, размер и SHA256, путь
установки под переносимым Java home, registry origin и точный model manifest.
Рецепт повторно проверяется после подготовки. В EXE нет запасных версий,
URL, хешей или модели; старые дескрипторы без рецепта можно читать для RAM,
но подготовка файлов по ним завершается понятной ошибкой. Проверяются повторное
использование кеша, смена рецепта и его binding во время скачивания, строгие
типы/дубликаты/границы, metadata JAR с настоящим mod ID, junction и UTF-8 BOM
при сохранении SHA256 всех исходных байтов. В Release входят восемь критических
случаев; весь набор доступен в Full. Сетевой fixture не запускает Ollama и не
подтверждает ответ настоящей модели.

`PortablePackSyncServiceTests.DownloadPlan_*` проверяют первую установку с
проверенным снимком `launcher/*` до большого payload, неизменный манифест при
смене release, повторное использование metadata asset, освобождение плана без записи
в сборку и локальный binding при офлайн-возврате. Изменение ранее исправного
управляемого файла после планирования отклоняется до скачивания и применения.
`PackPreparationDownloadTests` связывают производственные службы sync и AI:
первый большой payload уже имеет общий объём, кеш не запрашивается повторно,
докачка/повтор не выходят за бюджет, а офлайн-возврат не использует новый рецепт.
`PackDownloadProgressTests` проверяют абсолютные счётчики отдельных файлов,
границы, конкурентные сообщения и завершение только после проверки всех scopes.
Селектор для этого набора:
`FullyQualifiedName~DownloadPlan_|FullyQualifiedName~PackPreparationDownloadTests|FullyQualifiedName~PackDownloadProgressTests`.

`PortablePackSyncServiceTests.SourceWeight_*` проверяют резерв AI в RAM-оценке
до установки: только проверенные небольшие launcher assets, без JAR/runtime/model
и записи в игровую папку. Обычная сборка сохраняет нулевой AI-резерв и прежнее
число запросов; повреждённый рецепт, дескриптор, binding или смешанный asset
дают неизвестную оценку вместо заниженного резерва.

Дополнительные `LocalAiRecipeTests` проверяют `model.blobUrls`: адрес каждого
config/layer blob задаётся сборкой и остаётся под общим `recipeSha256`, набор
digest полный и точный, адреса проходят ту же HTTPS-проверку, что runtime.
Отсутствие `blobUrls` сохраняет прежний registry-путь рецепта; запасной рецепт
в EXE не появляется. Схема и поставка описаны в `tools/PACK-LIBRARY.md`.

PackLaunchContextTests проверяет необязательный дескриптор
`launcher/launch-context.json`: `{"schemaVersion":1,"requests":["localAi.endpoint"]}`.
Перед Java.Start лаунчер передаёт только запрошенный созданный им loopback HTTP
endpoint в `launcher-runtime/launch-context.json`:
`{"schemaVersion":1,"values":{"localAi.endpoint":"http://127.0.0.1:12345"}}`.
В этом файле нет унаследованного окружения, секретов и абсолютных личных путей.
Без дескриптора запись не выполняется. Неизвестные и повторённые поля/запросы,
неверные типы и отсутствующие binding отклоняются до записи. Фиксированный
instance-owned каталог защищён от поставки, копирования и удаления при sync;
неудачная атомарная замена сохраняет предыдущий файл. Статические правила и
запись конфигов выполняет код самой сборки. Каждый случай входит в Release.

PackLauncherFeaturesTests проверяет schema 2 с requiredLauncherFeatures,
включая `launch-context-v1` для дескриптора контекста запуска и
`local-ai-recipe-v1` для обязательного закреплённого AI-рецепта сборки.
Рецепт с собственными адресами всех model blobs объявляет
`local-ai-blob-urls-v1`.
Неизвестная обязательная функция требует обновить лаунчер до загрузки файлов;
отказ не маскируется офлайн-кешем. Старые schema 1 без features сохраняются.
Критический сценарий также включён в Release.

## Предзагрузка и первый кадр

`UiPreloadTests` проверяет повышение приоритета, отсутствие повторов, отмену очереди и сохранение страниц. `PackCatalogTests`, `WindowCanvasTests`, `LibraryTreeMotionTests`, `DialogLayoutTests` и `RenderingStartupTests` проверяют библиотеку, навигацию, геометрию и сохранение SoftwareOnly. Дополнительный стенд: `tools/UiPreloadProbe/README.md`. Результаты стенда сохранять только внутри artifacts. Нагрузка процесса/ОС и время CLR не входят в измерение конструктора окна. Самостоятельное моделирование RenderTargetBitmap не является проверкой реальных интервалов кадров.

В Release дополнительно включены 11 случаев предзагрузки: восемь настоящих popup всех четырёх списков до/после скрытой подготовки, сохранность layout slot принадлежащего родителю элемента и два завершения обработки крупного замороженного превью вне видимого дерева. Ещё два случая воспроизводят поздний callback анимации после отмены и во время закрытия уведомления. Source изображения остаётся оригинальным и при показе: подготовленный bitmap используется только в OnRender, не меняя измерение и пропорции контрола. Все прежние 520 случаев сохранены. Реальные замороженные превью обязательны: незамороженное временное изображение не запускает worker масштабирования и скрывает эту регрессию.

В Release добавлены ещё пять случаев: три настоящих окна с шестью замороженными превью при DPI 100/150/200% проверяют прокрутку до последней строки через реальные кадры, два случая закрепляют первенство списка запуска и пользовательский приоритет новостей. Все прежние 533 случая сохранены. Режим `--six-packs` у MeasureLayout создаёт шесть карточек для визуальной проверки: встроенные записи дополняются копией только внутри стенда, без изменения каталога лаунчера.

В Release добавлены 16 случаев PackCatalogStagedStartupTests: фактическая SyncAsync выбранной сборки при остановленных загрузках карточек, единый запрос и фиксация манифеста, удаления и пустой индекс до фоновой библиотеки, повреждённый офлайн-кеш, перенос источника между сеансами, общие источники пользовательских папок и офлайн-запуск установленной сборки с защитой прерванного обновления. Все прежние 538 случаев сохранены. Готовность выбранной игры проверяется отдельно от IsReady всей библиотеки; готовность контрола меню сама по себе больше не считается приёмкой запуска.

Отдельный случай действительно дожидается 15-секундного сетевого тайм-аута индекса: после исчерпания общего бюджета выбранная сборка использует проверенный кеш, не начиная второе такое же сетевое ожидание. Новый выбор получает собственный бюджет; отмена закрытием по-прежнему отменяет работу.

Раздельные замеры списка, выбранной сборки и полного фона выполняются стендом [CatalogStartupProbe](../tools/CatalogStartupProbe/README.md). Он использует изолированную копию кеша и пустые файлы с теми же именами, не запускает игру и не обращается в сеть. Фикстура и результаты остаются в artifacts; сеть в этих замерах не учитывается. Для сравнения использовать свежие процессы и отдельно указывать прогретость файлового кеша ОС.


## Ошибка памяти и подтверждение доставки отчёта

Изменения политики heap из выпусков 436 и 437 отменены: при Xmx выше 4096 МиБ восстановлен Xms=Xmx, при меньшем heap Xms равен min(1024 МиБ, Xmx). Предварительного ограничения по доступному commit и принудительного MaxHeapFreeRatio=100 нет; выбор RAM и файлы сборок не переписываются. MinecraftLaunchFailureTests проверяет реальную композицию CML и короткий диалог для native allocation/Windows 1455, 8, 14. Классификация JVM использует только консоль текущего процесса; старый latest.log и generic VM exit или Java heap OOM сами по себе не превращают другую ошибку в нехватку системной памяти. Полные технические подробности сначала записываются в журнал.

BugReportAcknowledgementTests работает на in-memory peer transport с синтетической средой. Записанные в транспорт байты ещё не считаются доставкой: ожидаются корректные Accepted, затем Stored с тем же ReportId, протоколом и совместимой версией. Проверяются удержанный финальный ответ, SHA256/длина payload, неверные и отсутствующие поля обоих ответов, отказ, JSON null и разрыв соединения. Protocol, Version, Stage и ReportId должны присутствовать в самом ответе; значения DTO по умолчанию не считаются подтверждением. Успех означает подтверждённое получение и сохранение, а не прочтение человеком; потеря ответа означает неподтверждённую доставку. UI-тесты закрепляют диалоги результата, сохранение нового черновика и отсутствие окон при закрытии. Настоящие пользовательские отчёты эти тесты не отправляют.

Для визуальной проверки коротких сообщений используются скомпилированный NoticeDialog, ресурсы App.xaml и настоящие системные шрифты:

```powershell
# messages.json: массив объектов Name/Heading/Detail; вход и результаты хранятся в artifacts.
dotnet run --project tools/MeasureNotice -- artifacts/notices/messages.json artifacts/notices/rendered
```

[MeasureNotice](../tools/MeasureNotice/README.md) проверяет ширины клиента 568/440/280 DIP и DPI 100/150/200%, сохраняя PNG и layout.json. Стенд не запускает Steam, игру или отправку отчётов. Снимок содержимого не заменяет проверку системной рамки и физического ввода.

## Единый обзор библиотеки, общие названия и фон окна

PackCatalogOverviewTests проверяет отдельный неизменяемый снимок обзора: полный проверенный cache/seed-набор публикуется вместе до свежих запросов карточек, а результаты свежей проверки заменяют его одним пакетом. Частичные результаты доступны внутреннему Find, но не staged Packs/PacksForDisplay. Удаления и пустой индекс применяются сразу; повреждённый кеш не считается готовым, отмена не публикует частичный новый набор, файлы установок и миров сохраняются. Выбранная игра не ждёт этого барьера; проверки свежего манифеста перед каждым «Играть» сохранены.

LibraryStartupRefreshTests теперь закрепляет одновременную публикацию обзора, состояние неизменившейся открытой страницы и безопасное закрытие. LibraryOverviewPreparationTests проверяет прогрев скрытого обзора без создания неоткрытых деталей, удаление открытой страницы выведенной из каталога сборки и левый якорь фиксированных карточек. Подробности подготавливаются по открытию с пользовательским приоритетом; готовность обзора не требует полного дерева каждой сборки.

PackDisplayNamesResolverTests проверяет единый источник проверенного отображаемого названия для библиотеки, выбора, игрового заголовка, пиров, миров и отчётов. Проверяются aliases, изменения/удаления/пустой снимок, конфликтующие имена, изоляция установок и отсутствие записи в пути, world ownership или wire identity. Проверенное `Content.Name` используется дословно, включая переименование только регистром букв; встроенное написание не подменяет новое авторское имя. Общая резервная нормализация регистра читает встроенный JSON-снимок, подготовленный из проверенных метаданных, без названий конкретных сборок в C#. Этот снимок не добавляет карточки в каталог. Непроверенные авторские файлы не подменяют проверенный снимок.

PreparedWindowBackdropTests проверяет frozen bitmap фона в текущем физическом клиентском размере, DPI 100/150/200%, последнее поколение после resize/смены ресурса, закрытие с worker, ошибку с исходной кистью как fallback и отсутствие кеша для простой однотонной кисти. Непрозрачный фон получает Bgr32 без потери цвета; прозрачный сохраняет premultiplied alpha в Pbgra32. Исходная поверхность сохраняется; интерактивные элементы и текст не растрируются. Один STA worker с пониженным приоритетом готовит только текущий размер, а неподходящая для временного кеша большая поверхность использует исходную кисть без снижения качества.

PreparedStaticRenderingTests сравнивает подготовленную обрезку UniformToFill с настоящим Image в текущем viewport при DPI 100/150/200% попиксельно, сохраняя исходный Source, layout и прозрачность. Непрозрачное превью использует Bgr32, прозрачное сохраняет Pbgra32. Общая очередь изображений выполняет растеризацию последовательно на одном STA-потоке с приоритетом BelowNormal, повышает приоритет видимых запросов и пропускает устаревшие варианты до выделения пиксельного буфера. Дополнительно проверяется повторное использование frozen rounded clip до изменения геометрии.

SmoothScrollingTests закрепляет расчёт прокрутки и возвратной пружины по фактически прошедшему времени: один задержанный кадр в 150 мс даёт то же положение, что девять обычных кадров за то же время. Долгая пауза ограничена 250 мс, чтобы возобновление окна не вызывало неограниченный скачок. Оба сценария проверяют обычную прокрутку и пружину у края.

Производительные замеры выполнять последовательно в свежих процессах, отдельно от сборок и тестов с анимациями:

```powershell
dotnet run --project tools/UiPreloadProbe -- . artifacts/performance/first-frame.json --first-frame
dotnet run --project tools/UiPreloadProbe -- . artifacts/performance/maximized.json --maximized --native-dpi --backdrop both --repeat 3
dotnet run --project tools/UiPreloadProbe -- . artifacts/performance/restored.json --restore --native-dpi --backdrop both
```

[UiPreloadProbe](../tools/UiPreloadProbe/README.md) использует изолированный root, synthetic cards с проверенным переполнением и фактическим движением viewport. Он фиксирует клиентские пиксели/DPI, Dispatcher Input, интервалы CompositionTarget.Rendering и CPU; --backdrop both сравнивает исходный и подготовленный фон. Синтетический layout DPI не доказывает физический 4K-дисплей. Эти данные и офлайн bitmap-проверки не являются игровым smoke, измерением FPS Minecraft или подтверждением прочтения настоящего отчёта пользователем.


## Изоляция ASM и очередь открытия мира Fabric

Адаптер содержит закреплённый ASM 9.8 в закрытом пакете `minecraft.portable.internal.asm`, а агент уведомлений — в отдельном `minecraft.portable.notice.internal.asm`. Оба подключённых Java-агента не добавляют второй публичный `org.objectweb.asm` в classpath Fabric 0.19.5. `IdentityAdapterAsmPackagingTests.BundledAsm_IsPrivateAndWorksWithOrWithoutTheLoadersAsm` запускает настоящий JVM с обоими активными агентами, отдельно без внешнего ASM и с ASM загрузчика, проверяет единственный публичный источник классов, работу закрытых core/tree и bootstrap-only hooks. Этот случай входит в обязательный Release; полноценный запуск Fabric остаётся отдельной игровой проверкой.

Обязательная возможность `private-identity-asm-v1` допускается только в манифесте сборки версии 2. Прежние лаунчеры отклоняют неизвестную возможность до загрузки файлов и предлагают обновление. Это общий контракт совместимости, без списка имён сборок.

Для отложенного закрытия native ShareToLanScreen общий поиск сначала использует `schedule(Runnable)`, затем `tell(Runnable)`. На Minecraft 1.21.1 настоящий `tell` (`method_18858`) ставит действие в очередь, тогда как `Executor.execute` может выполнить его внутри `init`. Существующая обязательная lifecycle-проверка дополнительно выполняет режим `queued-tell`: публикация одна, native init завершён до закрытия, resize не публикует повторно. Теория выбора маппинга и приоритета старого schedule также входит в профиль Adapters.

Прямые и intermediary-профили Fabric/Quilt входят в обязательный Release тремя случаями: проверяются фактическое имя фабрики заголовка и точный native target для preflight. Общая изоляция ASM проверяется настоящей JVM с обоими агентами лаунчера и отдельной ASM загрузчика.

Одиннадцать обязательных случаев общего resolver проверяют переименование через единственное проверенное Content.Name, точный регистр автора, сетевое чтение и офлайн-кеш, подписи игроков/миров, заголовок и отсутствие повторного уведомления о запуске. ID, пути и сетевые данные сохраняются.

## Короткие и полные проверки адаптеров

`Adapters` содержит 94 случая по 58 точным методам: основные текущие семейства Forge/NeoForge/Fabric, выбор Java и transport, точные JAR/SHA, native маппинги, личность и скины, LAN/discovery, pause reporting и управление очередью чанков. Это общие механизмы платформ, без отдельных копий для каждой сборки. Тесты зависящих от состава модов сценариев принадлежат самим сборкам.

`AdaptersFull` сохраняет прежний фильтр полной матрицы, в ранее зафиксированном прогоне 253 случая. Туда вынесены дополнительные сочетания транспорта, исторические комбинации заголовков и служебные представления маппингов. Полный профиль полезен при существенном изменении общего адаптера; он не обязателен для публикации одних данных сборки. `Full` также сохраняет все исходники проверок.

После сокращения новый прогон не выполнялся. Количество короткого набора сверено с текущими Fact/InlineData и прежним Adapter TRX; 52 случая также присутствуют в успешном Release760, 42 имеют прежнее адресное Adapter-покрытие. Отсутствующие в этой ревизии Legacy Fabric проверки не объявляются пройденными: при включении соответствующего универсального кода его владелец добавляет необходимые smokes и native preflight. Актуальный состав библиотеки задаётся каталогом GitHub; число сборок не является числом unit-тестов. Публикация новой карточки не подменяет проверку новой возможности общего адаптера.


Если нужны оба коротких профиля для одного изменения, используйте `Test-Launcher.ps1 -Profile Release -WithAdapters`. Скрипт объединяет точные имена методов и удаляет повторы до запуска, сохраняя тот же строгий TRX-контроль. Объединённый профиль содержит 382 метода и 625 уникальных случаев. Общие 15 методов и 20 случаев исполняются один раз. Матрица формируется из текущих файлов при каждом запуске.

Других больших обязательных автопрогонов нет. `Full`, `AdaptersFull`, подробные runtime/AI/геометрия/память и диагностические инструменты остаются адресными. Не повторяйте tools/Test-GuestMovement.ps1 после того же IdentityAdapterGuestMovementHelperTests: тест уже вызывает этот сценарий, отдельный запуск не является независимым подтверждением. При авторском обновлении сохранность QA-файлов не заменяет пересмотр сценариев и доказательств для новой версии.

IdentityAdapterExtractionTests проверяет обновление при занятом прежнем JAR, повторное использование занятого актуального JAR и восстановление повреждённого кеша. Версии адаптера лежат по SHA256 внутри папки лаунчера; прежний файл не перезаписывается и остаётся доступным завершающейся сессии.

GameWindowPresentationTests добавляет пять обязательных случаев: современное и старое первое ShowWindow, отключённый механизм, отказ иконки без скрытого окна и неизменность исходных runtime-иконок. Настоящие LWJGL 2/3 и Windows HICON проверяются отдельно tools/InitialWindowProbe; это не повтор QA-аудита сборок и не запуск игры.

Проверка обновлений интерфейса повторяется до подтверждённого ответа с паузами 5/10/20/30 секунд (далее 30). Отмена завершает ожидание без следующего запроса; предзапусковая проверка сохраняет прежний ограниченный режим.

При 504/сетевой ошибке прямого URL лаунчера резервный путь читает свежую запись релиза через API GitHub и скачивает asset по числовому ID с Accept: application/octet-stream. SHA256 и размер из метаданных проверяются до использования манифеста; файлы дополнительно совпадают с проверенным манифестом. Четыре обязательных случая закрепляют подтверждение текущей/новой версии и отказ при подмене байтов/имени.
