# Проверка настоящей перерисовки окна

Стенд показывает настоящий `MainWindow` с ресурсами `App` и штатным `WindowsThemeService`. Перед показом удаляются только обработчики запуска и закрытия, поэтому Steam, сеть, обновления и пользовательские игровые данные не используются. Каталог содержит отдельный fixture со встроенными превью. Собственный HTTP-handler отклоняет любой случайный сетевой запрос. Исполняемый файл и результаты должны находиться внутри `artifacts`.

```powershell
dotnet build tools/WindowRepaintProbe -p:SkipPortableIdentityAdapter=true

# Штатный прозрачный HwndTarget под Mica; SoftwareOnly и полный present.
artifacts/window-repaint-probe/bin/Debug/net10.0-windows/win-x64/WindowRepaintProbe.exe . artifacts/performance/repaint-transparent

# Диагностика: непрозрачный Canvas под заранее известным непрозрачным fixture.
artifacts/window-repaint-probe/bin/Debug/net10.0-windows/win-x64/WindowRepaintProbe.exe . artifacts/performance/repaint-opaque --opaque-client

# Отдельный новый процесс для экспериментального incremental present.
artifacts/window-repaint-probe/bin/Debug/net10.0-windows/win-x64/WindowRepaintProbe.exe . artifacts/performance/repaint-incremental --incremental

# Только диагностический процесс: аппаратный режим для сравнения.
artifacts/window-repaint-probe/bin/Debug/net10.0-windows/win-x64/WindowRepaintProbe.exe . artifacts/performance/repaint-hardware --hardware
```

По умолчанию проверяются главное окно, обзор библиотеки и детальная страница. `--screen main|overview|detail` ограничивает сценарий; `--original-backdrop` оставляет исходную кисть без подготовки статического фона. `--opaque-client` является только диагностическим override для этого непрозрачного fixture: штатный лаунчер сохраняет прозрачный target под Mica, без общего анализа непрозрачности. Каждое сравнение запускать последовательно, в новом процессе, без параллельной сборки, тестов или производительных стендов. Режимы не меняют настройки опубликованного лаунчера.

Окно временно показывается поверх остальных без активации. Проверяются первый показ, подготовленный фон, увеличение/уменьшение через `SetWindowPos`, три системных maximize/restore, minimize/restore и прокрутка в обе стороны. Сохраняются настоящий DPI, размер client rect, текущий цвет очистки HwndTarget, SoftwareOnly, состояние switch и признаки системной рамки с поддержкой изменения размеров и максимизации. Это не автоматизация Windows Snap и не проверка другого физического монитора или изменения системного DPI.

Снимок снимается с настоящего рабочего стола через `BitBlt` после `DwmFlush`, до создания независимого WPF RenderTargetBitmap для сравнения. После первого ContentRendered и переходов даётся 600 мс обычной обработки сообщений на завершение анимаций DWM: событие WPF само по себе не означает окончания системного появления или восстановления окна. Стенд не использует `PrintWindow`, `WM_PRINT`, искусственную инвалидацию или таймер перерисовки, которые могли бы скрыть чёрный или устаревший кадр. Проверка принадлежности HWND по сетке отклоняет закрытое другим окном или вышедшее за рабочий стол содержимое. Перекрытый экран не считается PASS.

Для каждого шага сохраняются `*-expected.png` и `results.json`; `*-actual.png` и `*-diff.png` записываются только для прошедшего проверку кадра. Непроверенный кадр может содержать просвечивающее постороннее окно во время системной анимации, поэтому его пиксели не сохраняются. Критерии: средняя абсолютная RGB-ошибка не выше 12, p95 ошибки средних плиток 32×32 не выше 25, доля пропавших в чёрном светлых пикселей не выше 0,5%, точный цвет обновляемой метки с допуском 3 и сохранённые системные frame styles. Разница текста ClearType и офлайн-оракула допускается; крупные чёрные области, старый размер/кадр и старая метка отклоняются. Ошибка делает код выхода ненулевым. Изображения нужно дополнительно просмотреть перед изменением режима рендера: численные пороги не заменяют визуальную оценку.

Доказательство ограничено записанными переходами, текущими Windows, DWM, видеодрайвером, DPI и монитором. Стенд не подтверждает универсальное отсутствие проблем на всех компьютерах. Результаты не являются измерением интервалов кадров; для производительности применяется `tools/UiPreloadProbe`.
