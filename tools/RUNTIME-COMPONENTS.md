# Отдельная поставка компонентов игры

Исходники служебных Java-компонентов и данные совместимости находятся в публичном репозитории [LANMinecraft-Components](https://github.com/MarkZamore/LANMinecraft-Components). Исполняемые файлы публикуются в неизменяемых релизах. `catalog.json` ветки `main` указывает на текущую проверенную поставку.

## Подготовка и запуск

Первый запуск после перехода на эту схему требует интернета. Лаунчер получает каталог с ограничением размера, проверяет версию схемы и контракта, происхождение ссылок, размеры и SHA-256. Каталог включает Java 8/17/21/25, правила выбора Java, проверенные сборки e4steam и правила выбора служебных компонентов. Архивы Java загружаются из закреплённых официальных источников Adoptium, e4steam — из его собственного репозитория.

Перед подготовкой игры лаунчер проверяет свежий каталог. Один снимок применяется к целой подготовке и запуску. В нём выбираются игровой адаптер, агент уведомлений, NativeInterop и вспомогательный установщик Forge по объявленной платформе сборки. Новые совместимые JAR и таблицы могут приходить без выпуска EXE. Новый контракт компонента или новый алгоритм разбора игровых файлов требует соответствующей поддержки лаунчера.

Файлы проверяются до атомарной регистрации в `Minecraft/Launcher/Components/objects/<sha256>/`. Один объект используется несколькими сборками. Сама Java использует существующий общий каталог `Minecraft/Launcher/JavaRuntimes`.

Для подготовленной сборки сохраняется закреплённый снимок и состав компонентов. При недоступности сети используется этот проверенный набор. Если нужных файлов нет, подготовка сообщает о необходимости подключения. После успешной сетевой подготовки следующий запуск проверяется также при полностью отключённой сети.

Результат префлайта зависит от конкретной сборки, игрового каталога, JAR, mappings и выбранной поставки. Переиспользование одного файла адаптера сохраняет отдельную проверку каждого окружения.

## Уборка

Уборка выполняется один раз после запуска лаунчера. Она учитывает закрепления установленных сборок, текущую подготовку и живые процессы с проверкой PID и времени старта. Подготовка держит файлы открытыми до регистрации процесса. Записи живых сессий защищают компоненты после закрытия и повторного открытия лаунчера.

Невостребованные объекты, прежние каталоги извлечённых адаптеров и брошенные загрузки удаляются после проверки ссылок и занятости. При нечитаемых данных ссылок удаление откладывается. Компоненты подготовленных офлайн-сборок остаются закреплёнными до успешной смены их набора. Резервные поколения старой архитектуры для совместимости не сохраняются.

## Разработка и выпуск

Компоненты собираются и проверяются в собственном репозитории. Публикация сначала загружает файлы неизменяемого релиза, затем обновляет указатель каталога. Изменения общих Java-компонентов и данных имеют собственный номер поставки.

Контрактные проверки лаунчера используют исходники второго репозитория по закреплённому коммиту и проверенные зависимости. `tools/Prepare-ComponentTests.ps1` переиспользует чистый checkout в `%LOCALAPPDATA%/LANMinecraft/DevCache/ComponentSources/<sourceCommit>` и передаёт его адрес в `LANMINECRAFT_COMPONENT_TEST_SOURCES`. Опубликованные двоичные зависимости хранятся отдельно внутри `artifacts/agent-runs`. Режим кандидата проверяет точный коммит готового checkout; порядок его выбора описан в [TESTING.md](../Program.Tests/TESTING.md). Обычная сборка EXE получает только код лаунчера. Изменения EXE проходят обязательный профиль `Program.Tests/Test-Launcher.ps1 -Profile Release`; изменения контрактов дополнительно проверяются полной матрицей адаптеров.

При продолжении на другом ПК получить оба репозитория и выполнить подготовку тестовых зависимостей. Канонические исходники хранятся в Git, результаты приёмки и временные игровые папки — в `artifacts/agent-runs` с владельцем, бюджетом и сроком удаления в `RUN.json`.
