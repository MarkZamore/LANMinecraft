# Проверка подключения Forge и публикации Steam-мира

Исправление общего лаунчера по отчётам от 8 ноября 2026 года. Сборка
Minecraft 1.20.1 / Forge 47.4.0 дала два независимых наблюдения:
ошибку `ConcurrentModificationException` при входе и выключение всех
общих hooks после отказа предпроверки клиентского списка серверов.
Личные журналы и идентификаторы игроков не входят в исходники.

## Подтверждения входа

В реальном журнале `Netty Server IO` падает в
`ArrayList.removeIf → HandshakeHandler.handleIndexedMessage:231`.
Проверенный Forge universal JAR имеет SHA256
`2b0e97b22fd4d043dbbcc8e0a44ef0d58915689ed9224e4cd28d5c4976a16bcc`.
Серверный tick добавляет индексы в `sentMessages`, сетевой поток удаляет
подтверждённые индексы. Исходный `ArrayList` не синхронизирован.

`ForgeHandshakeMappingService` выбирает только universal JAR выбранного
Forge из общего runtime. Содержимое папки модов не служит источником класса.
Новая проверка выполняется независимо от identity/skin hooks. Флаг
`forgeHandshakeSyncEnabled` включается лишь после успешной проверки
настоящего `net/minecraftforge/network/HandshakeHandler`.

`PortableForgeHandshakeTransformer` оборачивает только инициализатор
`sentMessages` в стандартный `Collections.synchronizedList`. Отдельные
операции add/removeIf/contains/isEmpty используют один монитор; весь tick
или callback не блокируются общим замком. Метод predicate ограничен штатным
сравнением индексов. Неоднозначная инициализация, изменение других полей,
escape списка, неизвестные consumers и field handles отклоняются.
Удаление единственной вставленной инструкции должно восстановить полный
исходный класс при ASM roundtrip. Исходные методы, порядок сообщений,
проверки входа и обработка исключений сохраняются.

Это изменение поведения Forge **в памяти** при загрузке класса существующим
общим адаптером. Файл Forge JAR и его версия не переписываются. Новый
контентный мод, framework и подавление CME не добавляются.

Почему поправка остаётся в лаунчере: внутренний список Forge handshake
не настраивается конфигом, datapack или обычным жизненным циклом сборки.
Текущий проверенный официальный исходник Forge 1.20.1 сохраняет такой же
список; исправление обновлением загрузчика не подтверждено. Замена
закреплённого загрузчика либо отдельный собственный mod/mixin потребовали
бы другого согласованного решения. Это общий механизм загрузчика,
не изменение механик контентного мода и не правило по имени сборки.
Другие Forge runtime получают поправку только при наличии выбранного
класса и прохождении той же строгой проверки ABI; игровой PASS для них
из одного прогона 47.4.0 не следует.

## Независимая публикация мира

Предпроверка локального Steam-списка у отправителя завершилась без
stdout/stderr, после чего выключилась и публикация метаданных мира.
Авторское Steam-лобби оставалось доступным оверлею. Первоначальная причина
ненулевого выхода Java на компьютере отправителя не воспроизведена:
настоящий LanList с заново полученными aliases проходит проверку локально.

Теперь отказ только клиентского семейства screen/list/entry допускает
отдельную проверку всех оставшихся целей. Публикация, skins и UUID hooks
сохраняются только после этой проверки. Пересечение aliases с другими
семействами запрещает исключение цели. Новый
`steamDiscoveryClientEnabled=false` выключает только непроверенные клиентские
transformers. `steamDiscoveryEnabled` и проверенный host publisher остаются
независимыми. Частичный результат перепроверяется при следующем запуске.
Проверка отражаемых getters имени игрока/мира требуется отдельно от
клиентского экрана, чтобы исключение экрана не исключало её.

Этот режим сохраняет видимость открытого мира для исправного клиента друга;
собственный клиентский список хозяина при отказе своей проверки остаётся
недоступен. Сообщение журнала описывает это ограничение. Ошибки Java теперь
сохраняют exit code, Windows hex-код и ограниченный вывод, включая явное
сообщение об отсутствии stdout/stderr.

## Проверки и границы

- [ForgeHandshakeProbe](ForgeHandshakeProbe/README.md) детерминированно
  воспроизводит CME исходного списка и проверяет исправленный вариант:
  неизвестный ACK не завершает вход, новый неподтверждённый индекс
  сохраняется, исключения predicate не подавляются, соединения имеют
  независимые замки. Native-режим исполняет изолированные исходные
  инструкции точного Forge 47.4.0, а не переписанную модель алгоритма.
- `ForgeHandshakeAdapterTests` проверяет выбор источника и независимый
  результат проверки при выключенной identity; отказ не включает флаг.
- `IdentityAdapterDiscoveryFallbackTests`, cache и Java discovery fixture
  проверяют сохранение host metadata, запрет обхода обязательных целей,
  повторную проверку частичного результата и отключение клиентских hooks.
- `tools/IdentityPreflightProbe` заново получает production mappings без
  запуска игры; `Verify-IdentityAdapter.ps1` позволяет проверить выбранные
  настоящие native-цели. Старый title-only state не доказывает проверку
  ранее исключённых целей.

Результаты обязательных Release/Adapters и точные native-прогоны фиксируются
в отчёте выпуска. По явному указанию пользователя повторный игровой прогон
на компьютере отправителя не выполняется. Реальный двухклиентский вход
после правки этим документом не объявляется проверенным. Исправление
постоянных 30–40 FPS и иных причин разрыва не заявляется.
