# Проверка загрузки OpenAL из Unicode-пути

Инструмент использует установленный профиль CmlLib и неизменяемые общие игровые
библиотеки. В собственном `artifacts/agent-runs/<task>` он распаковывает только
нативные DLL, компилирует небольшой Java 8 probe и проверяет реальный OpenAL PCM
с нулевой громкостью. Миры, настройки и моды пользователя не копируются.

```powershell
dotnet build tools/NativeInteropProbe/NativeInteropProbe.csproj
dotnet tools/NativeInteropProbe/bin/Debug/net10.0-windows/NativeInteropProbe.dll <repository> <output> <prepared-runtime-root> <game-java-home> <compiler-jdk-home>
```

Сначала соберите актуальный `Program` в Debug с настоящим JDK 25.0.2. Probe
ссылается на эту сборку без повторного изменения общих `Program/Build` JAR.
Каталог результата должен иметь владельца и срок удаления в `RUN.json`.

Проверяются ASCII-контроль, исходная ошибка кириллицы при UTF-8, исправление
с производственным агентом, независимый загрузчик классов, длинный Unicode-путь
и инициализация настоящего Knot с профилем Minecraft до вызова игрового main.
Отдельный случай с DLL-путём около 256 символов фиксирует ограничение старого
Windows/Java loader: ожидаемая ошибка слишком длинного пути не считается
успешной инициализацией звука и сохраняется как `knownWindowsPathLimit`.
Последний сценарий проверяет жизненный цикл модлоадера и его классы LWJGL,
но не заменяет игровой прогон или проверку слышимого звука на чужом ПК.
Предел дочернего процесса — 45 секунд; свои процессы завершаются при таймауте.
В `finally` удаляется только текущий staging; остаются компактные логи и JSON
с исходными SHA256, результатами, кодировкой и границами проверки.
