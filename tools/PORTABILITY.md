# Портативность лаунчера

Лаунчер распространяется одним EXE и не требует установки .NET или Visual C++ Redistributable. Основной режим отрисовки и проверочные стенды используют SoftwareOnly; переключения режима нет. Программная отрисовка сама по себе не изолирует файловую систему.

## Что находится в папке лаунчера

Начиная с новой упаковки, `Program/Publish.ps1` собирает обычные self-contained файлы .NET и вкладывает их без сжатия в native-хост. До запуска CLR хост проверяет встроенные данные и копию файлов в `Minecraft/Launcher/Runtime/<SHA256>`. Приложение выполняется в том же процессе: корень, имя EXE, значок и цель обновления сохраняются. Установленный в Windows .NET не используется для запуска этого EXE.

| Данные | Расположение относительно EXE |
| --- | --- |
| CLR, WPF и файлы приложения | `Minecraft/Launcher/Runtime/<SHA256>` |
| Временные файлы процесса | `Minecraft/Launcher/Temp` через ранние process-only `TEMP` и `TMP` |
| Возможные дочерние .NET bundles | `Minecraft/Launcher/DotNetBundles` через ранний `DOTNET_BUNDLE_EXTRACT_BASE_DIR` |
| Кеш анализа модулей помощника PowerShell | `Minecraft/Launcher/PowerShell/ModuleAnalysisCache` через `PSModuleAnalysisCachePath` до запуска помощника |
| Подготовленные фон, изображения и поверхности окна | Только оперативная память до закрытия окна |

Все файлы активного runtime проверяются до загрузки DLL. Повреждённая или недописанная собственная копия восстанавливается из EXE; ошибки не переводят распаковку в системную Temp. Ссылки, неожиданные файлы и выход за корень отклоняются. Подготовку согласует блокировка, а работающую копию защищает lease. Очистка сохраняет активные копии и две последние неиспользуемые; неизвестные, связанные, недоступные и занятые деревья не удаляются. Маленькие маркеры владения остаются для безопасного согласования с новым запуском.

Поддерживаемые API запуска описаны в [.NET native hosting](https://github.com/dotnet/runtime/blob/v10.0.2/docs/design/features/native-hosting.md). Подробности формата, сборки и антивирусной проверки находятся в [Bootstrap/README](../Program/Bootstrap/README.md). Настройка кеша PowerShell описана в [Windows PowerShell 5.1](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_windows_powershell_5.1).

## Что полностью перенести не удалось

| Остаток | Почему остаётся за пределами папки |
| --- | --- |
| `StartupProfileData-NonInteractive` в `%LOCALAPPDATA%/Microsoft/Windows/PowerShell` | Это отдельный профиль оптимизации Windows PowerShell 5.1. `PSModuleAnalysisCachePath` управляет другим кешем; поддерживаемого перенаправления этого профиля не найдено. Помощник обновления остаётся на штатном PowerShell. |
| `gameoverlay_renderer.txt` и `.previous.txt` в каталоге `Steam/logs` | Диагностика принадлежит установленному клиенту Steam. Поддерживаемого перенаправления этого журнала через используемый Steamworks API не найдено. |
| Записи оболочки, выбора файлов и текстового ввода Windows | Эти состояния обслуживают Windows Shell и CTF/TIP. Подмена переменных `APPDATA`, `LOCALAPPDATA` и `USERPROFILE` не перенаправляет Windows Known Folders; широкая подмена профиля также может нарушить работу зависимостей. |
| Кеши и диагностические записи самой Windows и видеодрайвера | Нет общего поддерживаемого механизма переноса всех таких записей для отдельного WPF-приложения. SoftwareOnly не отключает Windows/DWM и их учёт работы приложений. |

Строки PowerShell, Steam, Shell и CTF опираются на исторические локальные трассы 381/383 и проверку текущих путей в исходниках. Это **не полный список записей версии 443** и не новый результат «ноль записей снаружи». Полный новый Process Monitor capture не проводился: доступный наблюдатель требует повышенных прав, которых в сессии нет. Отсутствие новых файлов в отдельном наблюдаемом каталоге тоже не доказывает отсутствие всех системных записей.

Прежние кеши `%TEMP%/.net`, созданные старыми версиями, могут оставаться на компьютере. Новая упаковка их не использует; массово удалять общий кеш других копий приложения небезопасно. Настройки системы, драйвера, защиты и клиента Steam для сокрытия остатков не меняются.

Проверки запуска, путей, целостности, ссылок, параллельного доступа и очистки описаны в [TESTING](../Program.Tests/TESTING.md). Антивирусный результат относится только к проверенному файлу, текущим сигнатурам и машине; он не гарантирует отсутствие будущего эвристического срабатывания.
