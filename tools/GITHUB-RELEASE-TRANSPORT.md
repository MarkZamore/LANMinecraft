# Резервный официальный маршрут GitHub

Общий `GitHubReleaseTransport` применяется к манифестам и файлам сборок,
библиотечным bundles, управляемым компонентам, Java, установщикам и загрузкам
локального ИИ, а также обновлению лаунчера. Список сборок в нём отсутствует.
Остальные HTTP-источники сохраняют собственную политику загрузки.

После 504, сетевой ошибки или тайм-аута прямого GitHub Release URL транспорт
разбирает исходные owner/repo/tag/asset и запрашивает свежие метаданные через
официальный API. Для запроса прямых заголовков отводится восемь секунд,
оставляя время резервному пути в пределах дедлайна вызывающего сервиса.
Загрузка выполняется по числовому ID с `Accept: application/octet-stream`.
Проверяются уникальность имени, uploaded state, размер и SHA256.
URL из тела метаданных не исполняются: адрес API строится из проверенной
исходной ссылки и числового ID. Перенаправления API ограничены самим API
и разрешёнными GitHub CDN; затем ответ сопоставляется исходному логическому
адресу для прежних caller-проверок. Неоднозначный или непроверенный ответ
не становится разрешением запустить игру.

SHA256 и длина бинарного ответа проверяются потоком, без распаковки в RAM
целой сборки. JSON полностью проверяется до передачи парсеру. Далее остаются
независимые pins, лимиты, staging/rollback и границы каталогов вызывающего
сервиса. При резервном запросе Range сбрасывается: ответ 200 перезапускает
частичный файл с начала, позволяя проверить полный хеш. Прямой Range не меняется.

Метаданные бинарных файлов одного релиза переиспользуются до пяти минут
в пределах того же HttpClient; число записей ограничено. Каждый JSON-манифест
получает свежий запрос с защитой от кеша, включая каждое нажатие «Играть».
Удалённый asset сохраняет семантику 404 для существующего восстановления
сессии. Согласованный offline fallback и обязательность e4steam не меняются.
Если недоступны оба официальных маршрута, транспорт не подменяет проверку
успехом и не обходит целостность или обязательный компонент.

Адресные тесты находятся в `GitHubReleaseTransportTests`,
`LauncherReleaseAssetTests` и `PortablePackSyncServiceTests`.
Для живой проверки без личных миров и установок:

```powershell
dotnet build Program/Minecraft.csproj -p:SkipPortableIdentityAdapter=true
dotnet run --project tools/UpdateCheckProbe -p:BuildProjectReferences=false -- --release-matrix . artifacts/agent-runs/<task-id>
```

Сначала создаётся `RUN.json`. Проверка читает актуальный каталог, манифесты,
библиотеку и образец payload каждой записи, проверяет действующие Steam JAR
и конкретный bridge из исходного отказа. Прямому маршруту намеренно возвращается
504, API и CDN используются настоящие, без токена. Байты сверяются с pins,
но не устанавливаются в личные профили. Это адресная проверка доставки,
а не новый полный QA-аудит или успешный игровой запуск всех сборок.
Тот же сценарий доступен вручную через workflow
`verify-github-release-fallback.yml`; JSON результата содержит границы проверки.
