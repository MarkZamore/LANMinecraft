# Среда и ресурсы лаунчера

EXE содержит нативный загрузчик, приложение с его прикладными зависимостями и полный значок до 256×256. .NET/WPF, оформление и нативная Steam DLL поставляются тремя независимыми пакетами из [LANMinecraft-Components](https://github.com/MarkZamore/LANMinecraft-Components). `Program/Minecraft.ico` остаётся источником единственной встроенной PE-иконки.

Пакет оформления содержит фон, игровые значки, SVG интерфейса и архивы офлайн-карточек библиотеки. Канонические SVG находятся в `Program/Assets/Icons` лаунчера. Архивы генерируются штатным инструментом `tools/build_library_seeds.py`; JSON офлайн-каталога без изображений входит в приложение.

Для изменения только оформления выполните `tools/Sync-LauncherAssetSources.ps1 -ComponentRepository <checkout LANMinecraft-Components>` из лаунчера. Скрипт переносит проверенный набор SVG и архивов в рабочие исходники компонента и фиксирует размеры/SHA-256. После проверки упаковки опубликуйте отдельный неизменяемый тег `launcher-assets-N` репозитория компонентов. Тег запускает сборку, проверку воспроизводимости и публикацию собственного пакета, не дублируя .NET и Steam. В lock лаунчера заменяется только pin вида `assets`, включая неизменяемый URL, SHA-256 пакета и его таблицы, размеры и резервный URL GitHub API.

Для проверки кандидата до публикации используйте `tools/Build-LauncherAssets.ps1` из компонентов. Укажите `LANMINECRAFT_DESKTOP_TEST_ASSETS_CANDIDATE` на его выходной каталог с `launcher-assets.json` и `.pak`, затем запустите обычную подготовку desktop-тестов. Пакеты .NET и Steam переиспользуются из собственного кеша по digest.

## Закрепления и первый запуск

`tools/desktop-components.lock.json` закрепляет протокол, версии, источник, immutable release URL, резервный API URL, размер/SHA-256 пакета и размер/SHA-256 его таблицы файлов. `Build-PortableHost.ps1` записывает описатель `LMDESK01` в PE-ресурс 102; ресурс 101 содержит только пакет приложения. Приложение публикуется framework-dependent с точными версиями Core/Desktop из lock и отключённым roll-forward. Первая поставка использует 10.0.14, как версия 534.

Пакет `LMHOST01` несжатый: заголовок, упорядоченная таблица безопасных относительных путей и исходные байты файлов. Для внешнего пакета entry может быть вложенным `host/fxr/.../hostfxr.dll`, фоном или Steam DLL. Manifest — точный префикс заголовка и таблицы. Его независимое закрепление позволяет проверять распакованные файлы без сохранения полной транспортной копии.

До входа в CLR нативный WinHTTP worker подготавливает зависимости. Win32 окно в исходном потоке показывает этап, процент, объём, скорость, отмену и повтор после сетевой/обычной I/O ошибки. Retry использует Range; ответ 200 вместо 206 начинает текущий файл заново. Cancel во время загрузки и после ошибки удаляет текущий `.part`; уже проверенные компоненты не становятся повреждёнными. Код отмены — 1223, ошибки структуры/безопасности — 120.

Среда хранится в стандартном private layout. Hostfxr получает отдельные `appPath` и `dotnetRoot`; системная .NET не подменяет закреплённую среду. Сохраняются внешний PID, ProcessPath, STA, исходные аргументы, portable temp и штатная установка обновления с перезапуском.

CLR получает обычные пути DOS/UNC. Если полный путь нативного модуля среды достигает ограничения WPF `MAX_PATH`, используется существующее имя 8.3 после проверки того же физического каталога и его file ID. Нативные и managed PE определяются по проверенным заголовкам, включая ReadyToRun; длинные пути managed-ресурсов сами по себе не требуют имени 8.3. Если подходящего короткого пути нет, подготовка останавливается до CLR с сообщением о переносе папки ближе к корню диска. Запускатель не создаёт junction/symlink и не меняет системные настройки.

## Кеш и офлайн

Пути: `Minecraft/Launcher/Bootstrap/{app,desktop-runtime,assets,steam-native}/<hash>/`. Для приложения hash — digest тела встроенного пакета, для внешних компонентов — SHA-256 всего транспортного пакета. Таблицы и ownership leases лежат рядом с поколениями.

Нативная подготовка проверяет все файлы и удерживает read-only handles и leases до завершения приложения. Метаданные публикуются эксклюзивной записью с flush/hash и проверенным read guard до передачи context и managed entry. Физический rename не используется: он конфликтует с родительскими защитными блокировками. Незавершённая запись не принимается по hash и восстанавливается при следующей подготовке.

Процесс получает закреплённый `BootstrapLaunchContext`. Фон готов до разбора App.xaml, обе службы игровых значков читают внешний JAR, Steam resolver загружает только проверенную SDK-совместимую DLL. Сетевых обращений в этих managed resource readers нет. Значки Проводника, окна подготовки и панели задач используют полный встроенный ICO без последующего улучшения качества.

Исправный подготовленный bootstrap не обращается к сети и не показывает окно подготовки. Первый переход требует интернета. Офлайн-запуск требует сохранных закреплённых файлов; при их повреждении и недоступности сети предлагаются повтор и отмена. После загрузки EXE не увеличивается: компоненты остаются в `Minecraft/Launcher`.

После готовности UI сохраняются текущий и один предыдущий успешный набор. Стартовая уборка защищает их, staged references и любые активные leases; нечитаемые ссылки откладывают удаление. Старые flat `Runtime` удаляются только после успешного перехода и освобождения их leases. Пользовательские миры, настройки и файлы сборок не входят в эту уборку.

## Разработка и проверка

Перед отдельным `dotnet test` выполнить в том же PowerShell `tools/Prepare-ComponentTests.ps1` и `tools/Prepare-DesktopComponentTests.ps1`. Второй helper проверяет пакеты, таблицы и все файлы и переиспользует один кеш зависимостей. `Test-Launcher.ps1` делает это автоматически. Для CI нового desktop candidate поддерживается `LANMINECRAFT_DESKTOP_TEST_CANDIDATE` с новым catalog и тремя пакетами. Обычные фикстуры используют `LANMINECRAFT_DESKTOP_TEST_COMPONENTS`; production не использует их как запасной источник.

Нативные проверки обслуживают точные пакеты локальным HTTP fixture и управляют только собственными окнами/процессами через Win32. Loopback HTTP и scalar font hook разрешены только тестовым флагом сборки и отсутствуют в production. Сохраняются cold/warm/offline, отмена после ошибки, оба Range-сценария, repair, concurrency, unsafe paths, full ICO, DPI и updater roundtrip.

`tools/Measure-DesktopStartup.ps1` и `tools/DesktopStartupProbe` сравнивают нативный запуск, настоящие App/MainWindow, первый кадр и взаимодействие с интерфейсом. Loaded/Closing сервисов отключены в техническом host, поэтому это не замер Steam-подключения или полной подготовки игры. Стенд не использует SingleInstanceGuard и не трогает пользовательский лаунчер. Baseline 534 и кандидат запускаются попеременно; отчёт включает медиану/p95 и точные SHA. Первый сетевой запуск учитывается отдельно.

Сначала публикуются проверенные immutable компоненты, затем EXE с их pins, затем update.json. Основной выпуск содержит только полный EXE и update.json со штатными проверками. Клиент скачивает полный файл обновления; подготовленные компоненты используются повторно. Изменения игрового контента и правила отдельных сборок к этой поставке не добавляются.

## Замер перехода 534 → 535

18 ноября 2026 года выполнены 20 чередующихся прогретых запусков каждой версии на одном ПК с private Core/Desktop 10.0.14. Исходная сборка 534 взята из `553622c186c55a5105a6a56e1a5216a00107f4bc`; обе версии использовали один технический host, настоящие ресурсы App/MainWindow и пять офлайн-карточек.

| Показатель | 534, мс | Кандидат 535, мс |
| --- | ---: | ---: |
| Первый кадр, медиана | 596,831 | 600,088 |
| Первый кадр, p95 | 609,210 | 627,767 |
| Подготовка офлайн-библиотеки, медиана | 86,868 | 65,398 |
| Ввод и layout, медиана | 1,177 | 1,155 |
| Открытие библиотеки, медиана | 2,061 | 2,032 |
| Изменение размера, медиана | 6,236 | 6,305 |

Все пороги регрессии пройдены. В 40 из 40 запусков ровно одна отложенная Startup-операция конструктора WPF была отменена до обработки dispatcher, оставалась отменённой после кадра, существовало одно окно, личные файлы стенда не менялись, окно не получало активацию или foreground. Новый host сохранил успешный набор в 20 из 20 запусков. Полная готовность Steam/игры, физический ввод и холодный кеш Windows этим замером не проверялись. Предварительные прогоны без подавления Startup исключены из результатов. Воспроизводимые исходники и команды находятся в `tools/DesktopStartupProbe` и `tools/Measure-DesktopStartup.ps1`.
