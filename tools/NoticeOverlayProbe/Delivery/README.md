# Проверка уведомлений на настоящем клиенте

Это внешняя консоль проверки производственного `GameNoticeOverlayService`,
а не мод или отдельный игровой renderer. Она использует уже подключённый
лаунчером канал уведомлений. Все результаты направляются в собственный
`artifacts/agent-runs/<task-id>` с `RUN.json`.

```powershell
dotnet build tools/NoticeOverlayProbe/Delivery/NoticeDeliveryProbe.csproj
dotnet tools/NoticeOverlayProbe/Delivery/bin/Debug/net10.0-windows/NoticeDeliveryProbe.dll <root> <launcher-dll> <output> <game-pid> <delay-ms> [repeat-test-ms]
```

Допускается опубликованный `LANMinecraft.dll` внутри `Minecraft/Launcher/Runtime`
или локальный кандидат в `Program/bin`. Игра должна быть на переднем плане,
в настоящем полном экране без заголовка. Проверка сверяет границы монитора,
PID и время старта, требует ровно одну живую сессию и не трогает параллельную
игру. Она вызывает штатный `TryShow`, сохраняет SHA сборки, heartbeat,
`renderedCount` и неизменность foreground HWND в `delivery.json`.
Положительный heartbeat нужно дополнить наблюдением пикселей уведомления
на снимке игрового окна. Максимальные задержка и период повторов — 30 секунд;
повторы отправляют обычные уведомления с неизменным сроком жизни семь секунд.

Для сравнения опубликованного и исправленного агента `--launch` принимает
`<root> <candidate-dll> <output> <private-captured-launch.json> <style.properties>`.
Сначала запустите игру обычным лаунчером и сохраните её `ProcessId`,
`ExecutablePath`, `CommandLine` в закрытый JSON внутри стенда. Затем штатно
закройте исходную игру. Запись содержит личные аргументы: её нельзя
коммитить, публиковать или оставлять после проверки.

Повторный запуск переиспользует фактическую Java, classpath и неизменяемые
ресурсы. Копируются только mods/config/defaultconfigs/resourcepacks/options
в новый тестовый профиль; миры пользователя не копируются. Заменяется
только агент уведомлений и его каталог сессии, добавляется полный экран.
Создавайте тестовый мир только в этом профиле и завершайте игру штатно.
Не запускайте второй клиент одновременно. После проверки удалите закрытый
JSON, копию профиля, тестовый мир, временные файлы и выход сборки; оставьте
компактные JSON, снимки и описание границ проверки.

Этот сценарий подтверждает конкретный клиент на конкретном графическом
runtime. Он не доказывает совместимость всех сборок или будущих API.
