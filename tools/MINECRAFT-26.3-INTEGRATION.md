# Minecraft 26.3: обновление, LAN и общий e4steam

Подготовлено 28 октября 2026 года. Эта поставка продолжает прежнюю карточку Minecraft 26.2, обновляет платформу и EMI, переносит старую установку и использует общий компонент e4steam. Последнее решение пользователя исключает новый игровой прогон; установка платформы и Java-префлайты не запускают Minecraft.

| e4steam для всех установленных профилей | 0.3.4 | [Общий репозиторий владельца лаунчера](https://github.com/MarkZamore/e4steam/releases/tag/v0.3.4) |

Исходный профиль использовал Minecraft 26.2, NeoForge 26.2.0.84 и EMI build 59 того же Alpha-порта. Форк EMI не заменён другим проектом. В author source сборки активен один EMI; e4steam не включён в её Git, payload или счётчик игровых модов. Замены, SHA256, Safety-обоснование, SDL-пресет и граница active/legacy находятся в `tools/UPGRADE-26.3.md` репозитория [Minecraft-26.3](https://github.com/MarkZamore/Minecraft-26.3).

Стабильный ID библиотеки остаётся `minecraft-26-2`. Имя, папка и репозиторий становятся `Minecraft 26.3` / `Minecraft-26.3`. GitHub сохраняет перенаправление прежнего адреса.

## Причины исправлений адаптера

- Старый поиск mappings и authlib просматривал общий кеш других Minecraft. Для 26.2 выбирались MCP 1.20.1 и authlib 3/4 вместо реально загруженного authlib 9. Теперь выбор ограничен точным профилем и настоящим patched JAR загрузчика; необфусцированные версии читаются непосредственно из class-файлов.
- Authlib 9 использует неизменяемые профили, а authlib 10 перенёс session service и URL-проверку в `services`. Текстуры подставляются до записи immutable-свойств; при чтении обновляется только выбранная текстура. UUID, имя и посторонние свойства сохраняются. Исключение secure-проверки ограничено зарегистрированными профилями.
- В 26.3 настройки LAN переместились в общий `WorldOptionsScreen`. Обычные настройки мира сохранены. Отдельная native-строка открывает мир одним нажатием, затем открывает штатные жалобы. Автопубликация разрешена только для экземпляра, созданного этой строкой.
- e4steam 0.3.4 отменяет native `init` ради своего промежуточного экрана. Общий адаптер пропускает только точный проверенный redirect-вызов, сохраняя native body и остальные callbacks. Проверяются SHA выбранного авторского JAR, Mixin origin, descriptor, полный профиль handler и единственный caller/site. Это изменение runtime-поведения авторского компонента явно ограничено этим местом; сам JAR не перепаковывается.
- Проверка движения 26.3 перенесена через private position-handler и подтверждение телепортации. Разрешён только точный граф этих двух путей; проверки прав и посторонние callers не изменяются. Префлайт по-прежнему требует два адресных hooks.
- Заголовок использует общий producer лаунчера из версии 411 и показывает название папки сборки. Второй механизм заголовка не добавлен.

## Переименование и обновление

`PackRenameMigration` проверяет коллизии, живой процесс, `session.lock` и ссылки до переноса. Журнал позволяет продолжить прерванную операцию. Переносятся каноническая папка, instance, миры и runtime; обновляются принадлежащие лаунчеру ссылки и настройки. Обычный `saves` сохраняется, ожидаемый junction перенаправляется на новый путь. UUID, NBT мира, личные моды и `options.txt` не переписываются ради имени или скина.

Синхронизация использует exact-hash active/retired записи. Неизвестный или изменённый instance-JAR сначала сохраняется в `Personal/PackConflicts`, затем исключается из активного состава. Один проход подготовки использует один снимок конфликтов, поэтому лимит хранения пяти обновлений не уничтожает первые файлы одного большого обновления. Ошибка создания копии запрещает удаление оригинала.

После обновления лаунчера прежняя карточка и добавленная сборка получают новое имя. Новые файлы Minecraft, загрузчика и модов получает существующая подготовка при нажатии «Играть». Старый дисковый кеш библиотеки нормализуется по ID и aliases и не создаёт вторую карточку.

## Одна общая поставка e4steam

Все активные URL ведут только на `MarkZamore/e4steam`, по неизменяемому пути `releases/download/v<version>/<file>`. Авторские Kamilhik URL сохранены отдельно как provenance и не служат runtime fallback. Центральный Git содержит индекс, licenses/notices и инструменты публикации; JAR находятся только в release assets, по одному экземпляру каждого файла.

Для всех семи установленных профилей подходит 0.3.4. Полный каталог сохраняет 19 совместимых веток: шесть современных авторских JAR 0.3.4 и тринадцать ретро JAR 0.3.2, для которых автор не выпустил 0.3.4. Не создаются вымышленные универсальные JAR. Forge и NeoForge используют разные авторские файлы; совместимые сборки переиспользуют один кеш и одно скачивание. Старые официальные байты заменяются только после проверки новой загрузки; неизвестный JAR не принимается за прежний релиз по имени.

## Самостоятельная папка модов

Положите JAR в `Minecraft/Packs/<название>/mods`, затем выберите сборку и нажмите «Играть». Если `portable-pack.json` отсутствует и папка не принадлежит удалённому источнику, лаунчер читает метаданные, определяет общую совместимую версию Minecraft и загрузчика и сохраняет точный манифест. Затем работает обычный установщик платформы и общего e4steam. Явный манифест всегда имеет приоритет.

Учитываются Forge/NeoForge TOML, Fabric, Quilt и legacy Forge, диапазоны и альтернативы; FML language API отделён от версии платформы. Используются только стабильные официальные каталоги. Нераспознанный JAR, неподдерживаемое условие, противоречие или недоказанная неоднозначность не отбрасываются голосованием: выводится причина и имя файла. Сам код модов при определении не исполняется. Произвольные зависимости игровых модов не скачиваются автоматически.

Нужны достаточные ограничения Minecraft хотя бы у одного мода согласованного набора. Имя файла и суффикс версии не заменяют отсутствующие требования. Например, текущий авторский EMI не объявляет Minecraft-зависимость и сам по себе не доказывает 26.3; опубликованная сборка использует явный проверенный манифест. Quilt читает собственные метаданные раньше Fabric, а совместимость Fabric-модов проверяется по явному `fabricloader` alias настоящего официального Quilt JAR и его SHA256.

## Воспроизведение проверок

```powershell
$env:JAVA_HOME = 'C:\Tools\jdk-25.0.2'
.\Program.Tests\Test-Launcher.ps1 -Profile Adapters
.\Program.Tests\Test-Launcher.ps1 -Profile Release
.\tools\Test-GuestMovement.ps1
.\tools\Test-PortableSkinProfiles.ps1 -InstallRoot <Minecraft> -MinecraftVersions 26.3,26.2,1.21.1
```

Свежие aliases необходимо получать текущим mapping-service по соответствующим настоящим профилям. Старый `adapter-state.json` не становится актуальным после одной замены JAR. `Verify-IdentityAdapter.ps1 -StateJson <fresh-state>` проверяет bytecode и authlib semantics; это не подтверждение запуска клиента или двух игроков. Изолированный post-Mixin fixture использует реальные pinned handler bytes и `CallbackInfo`, но не объявляется выполнением Mixin engine.

Пользователь подтвердил выбранный скин и одно нажатие LAN на исходной исправленной 26.2. QA-мир был сохранён и закрыт. Для новой 26.3 по последнему решению пользователя игровой прогон не выполняется; итоговая приёмка опирается на исходники, проверку поставки, native preflight и автоматизированные проверки.

Финальные проверки: Release 421/421 по 247 методам, Adapters 214/214, без пропусков. Свежие production mappings и Java-префлайт: 26.3 10/10, 26.2 10/10, ATM10 16/16; семантика скина проверена на authlib 10, 9 и 6. Изолированный сценарий с одним настоящим JEI 15.20.0.116 подтвердил выбор Minecraft 1.20.1 / Forge 47.4.28 через официальные каталоги и установщик, затем загрузку e4steam 0.3.4 именно из общего репозитория владельца; исходный JAR не изменился, Minecraft не запускался.

Инструмент `tools/DeploymentPrep` отдельно проверен семью сценариями установки и безопасного отказа. Два совместимых типа транспорта для семи профилей потребовали двух загрузок, повторный проход не загрузил и не заменил ничего. Это репетиция на независимых данных; инструкция и границы проверки находятся в README инструмента.
