# Native desktop bootstrap regression host

This framework-dependent target links the shared `PortabilityAuditHost` diagnostic source. `NativePortableHostTests` packs its managed files into the real native launcher using one snapshot of the prepared fixture's `desktop-components.json`. The normal preparer derives that snapshot from `tools/desktop-components.lock.json`; external component CI can supply its freshly prepared candidate snapshot. The audit's exact runtime version comes from the same selection. No self-contained runtime is published into the application packet, and installed .NET cannot satisfy the tests.

Prepare shared packet fixtures once with `tools/Prepare-DesktopComponentTests.ps1`, then run the native test filter using the resulting `LANMINECRAFT_DESKTOP_TEST_COMPONENTS` environment variable. The test assembly also needs the existing `tools/Prepare-ComponentTests.ps1` environment for its module initializer. Invoke both helpers in the same PowerShell session as `dotnet test`; the normal launcher test wrapper does this preparation. The fixture verifies packet and manifest hashes before serving them read-only through a private loopback TCP listener. Only explicitly compiled test launchers accept these HTTP endpoints.

The disposable installation lives directly in one short marked `artifacts/agent-runs/n-<8hex>` directory with a 1 GiB reservation. Atomic directory creation and a `CreateNew` marker containing the full GUID prevent collision/reuse. This avoids an unnecessary installation subfolder and long diagnostic prefix on CI volumes without 8.3 names. Cold, warm/offline, cancellation, retry, byte-range resume, ignored Range, corrupt downloads/cache repair, simultaneous processes, Unicode paths, outer PID/STA, update reuse, full PE icons and manifest policies are checked through real native processes. No personal launcher installation or game data is an input.

The rendering probe creates the real launcher Application on an unpumped STA. While its dispatcher processing is explicitly disabled, a separate owned STA shows a small WPF window until `ContentRendered` and enumerates the normal tablet collection. This forces graphics and PenIMC activation without executing launcher startup services. It closes its HWND programmatically, then the original STA checks production resources/dialogs and shuts down. Runtime modules and 8.3 aliases are compared through verified physical handle paths; the reported application root must remain canonical. The cold/warm case also launches through an existing short executable alias when available.

Preparation UI checks address the exact newly-created process ID and the `LANMinecraft.BootstrapPreparation` window. They send native command/DPI messages, measure real child bounds and text with the selected fonts, and collect compact JSON. Synthetic `WM_DPICHANGED` cases cover 96/144/192 DPI layout without changing the user's display settings; the actual monitor DPI is recorded separately. No computer-use, desktop input, screenshots or manual confirmation is used.

The fixture stops only processes whose PID, creation time and executable image match its ownership record. Its final cleanup removes its application, extracted component caches, publish files and compiler staging after preserving compact logs. Shared component source packets remain owned by the preparer and are never deleted by the tests.

After an externally aborted test run, stop only its verified owned processes and use `Cleanup-Fixture.ps1 -RunDirectory <exact-run>` to preserve compact evidence and remove its recoverable bulk files. The helper requires the expected marker/owner/full identity, refuses running processes, links and Git metadata, and accepts only a direct owned `n-<8hex>` child of `artifacts/agent-runs` (plus historical marked `native-desktop-host-tests-*` runs). Cleanup removes generated EXEs and `Minecraft` while preserving diagnostic JSON/logs.
