# Derived legacy assets

Mojang asset indexes can declare `virtual` and/or `map_to_resources`. These flags
require filename-based copies alongside the content-addressed objects. CmlLib
reports the objects as required files, while the copies are generated by update
tasks. They must survive a shared-store sweep as long as a runtime owns their
index, including states written by older launchers.

The launcher derives the live copy paths from that same local index, repairs
missing or corrupted flat files from hash-checked objects on cached preparation,
and verifies the layout on fresh preparation. It does not download a different
library, change Java, or rewrite a pack setting. Index paths and junctions are
checked before restoring files. Runtime-state schema and cache generation remain
unchanged; an installed legacy runtime can recover offline.

`Verify-DerivedAssets.ps1` exercises the actual implementation from the built
launcher assembly against an actual index in an owned agent run. `-ResetCopies`
unlinks only declared copies inside that run, leaving source objects untouched.
It then verifies every destination SHA-1 against the index and requires a second
unchanged pass to rewrite zero files. This checks file delivery, not audible
playback or an OpenAL device on a remote PC. Never point this audit at a personal
instance, world, or installed shared store.
