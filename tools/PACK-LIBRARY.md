# Каталог библиотеки

Публикация только сборки или каталога не требует прогона Release-профиля лаунчера и нового EXE. Выполняются проверки её исходников, SHA/lock, метаданных, обязательных возможностей и согласованная приёмка фактического runtime. Сценарии конкретных модов и состава хранятся в QA-данных репозитория сборки. Общие тесты лаунчера и Minecraft-адаптеров остаются в LANMinecraft и запускаются при изменении их реализации. Если новая сборка требует изменения общего адаптера, проверка этого изменения относится к выпуску лаунчера; она не повторяется при последующей публикации одних данных сборки.

Видимое название задаётся только `library/content.json:name` и после проверки используется карточкой, списком запуска, заголовком игры, игроками, уведомлениями и отчётами. Переименование, включая смену регистра, не меняет ID, опубликованный путь, сетевые данные и принадлежность миров. До готовности проверенного снимка применяется локальное имя; его регистр уточняет маленькая встроенная копия тех же метаданных, без правил по именам сборок в C#.

В общем снимке отдельно индексируются пути папок (включая проверенные прежние пути) и стабильные ID. Элементы интерфейса и заголовок игры ищут по фактическому пути; поиск по ID вызывается явно. Поэтому совпадение имени посторонней локальной папки с ID каталоговой сборки не подменяет её название.

Список доступных сборок, карточки и выбор адреса источника читаются при старте. Перед каждым «Играть» лаунчер отдельно получает свежий игровой манифест этого источника, даже если обновление вышло при уже открытом окне. Уникальный параметр запроса и `no-cache/no-store` защищают изменяемый адрес; адреса файлов по SHA остаются неизменными. После проверки один снимок используется для размера загрузок, состава файлов и рецепта локального ИИ до завершения применения. Если сеть недоступна, согласованная установленная версия сохраняется с явным сообщением; отмена и неизвестная обязательная возможность не превращаются в успешный офлайн-запуск. Исчезновение файла уже выбранной ревизии требует повторить «Играть», а не перезапускать лаунчер.

Лаунчер читает `catalog.json` из ветки `pack-catalog` этого репозитория один раз при запуске. Образец индекса — `tools/pack-catalog.json`. Новая сборка регистрируется после успешной публикации её первого `pack-latest`: стабильный `id`, `relativePath` и `source` с `owner`, `repo`, `tag`. Само переименование GitHub-репозитория не меняет ID или папку. При изменении отображаемого имени укажите новое имя папки в `installationPath`, оставьте опубликованный `relativePath` и `id` прежними и перечислите все предыдущие локальные пути в `legacyRelativePaths` (сам `relativePath` добавляется автоматически). При смене источника сохраните прежний в `legacySources`. Сначала выпустите лаунчер с поддержкой поля, затем опубликуйте запись каталога. Старые клиенты продолжают использовать опубликованный путь, новые переносят существующие данные с журналом до готовности запуска. Связь со старым клиентом и метаданные при передаче мира используют опубликованный путь. Не заменяйте обновлённый EXE старым в той же папке после миграции. Ветка каталога не запускает выпуск приложения.

TerraFirma Rebirth 2 остаётся обновлением сборки с ID `terrafirma-rebirth`. При одновременной смене видимого имени и папки лаунчер до загрузки настроек переносит прежние `Packs`, личный экземпляр, миры и runtime, обновляет метаданные принадлежности миров и ссылку `saves`, сохраняя игровые файлы и персональные настройки. Миграция повторяется после прерывания, останавливается при конфликте старой и новой папок или занятом мире; маленькие изменяемые метаданные предварительно сохраняются в `Personal/Backups/PackRenames`. Проверенный старый кеш библиотеки использует новое имя и тот же ID.

Обновление сборки или её карточки публикуется только в репозитории сборки и при необходимости в ветке `pack-catalog`, без выпуска EXE. Стартовая синхронизация обновляет также название в списке запуска по проверенному `library.json:name`, сохраняя путь установки, выбор, настройки и принадлежность миров. Публичный `relativePath` TerraFirma остаётся `TerraFirma Rebirth` для совместимости уже установленных лаунчеров; новые версии понимают это имя как алиас перенесённой папки. Локальный `sourcePath` в `tools/pack-catalog.json` задаёт папку исходников `TerraFirma Rebirth 2` только для генератора встроенных снимков.

Состав списка задаёт только индекс GitHub. Проверенный сетевой или дисковый индекс полностью заменяет предыдущий состав, в том числе пустым списком. `Program/LibrarySeed/catalog.json` содержит снимок GitHub для первого запуска без сети, а не дополнительный список предложений. Удалённые записи исключаются из карточек и списка запуска; локальные игровые файлы, миры и байты кеша сохраняются. Источники явно пользовательских локальных сборок остаются отдельными. При временной ошибке манифеста сборки, которая всё ещё присутствует в индексе, остаётся её последний проверенный снимок; новый адрес становится активным после проверки.

Каждая сборка хранит `library/content.json` и `library/preview.jpg`. Описание пишется по реальному игровому содержимому; `libraryIds` отделяет вспомогательные библиотеки, `parents` задаёт проверенные отношения аддонов. Зависимости jar сами по себе не являются деревом аддонов. Названия и версии модов читает `tools/pack_library.py` из актуальных jar; версию Minecraft и загрузчик — из `portable-pack.json`.

В карточке и описании сборки после версии Minecraft показывается количество модов, например `Minecraft 1.21.1 (200 модов)`. Счётчик берётся из текущего `library.json`: это уникальные загружаемые mod ID, включая аддоны, библиотеки и вложенные зависимости JarJar выбранного загрузчика. Число JAR не заменяет этот счётчик. Служебные JAR без загружаемого mod ID остаются в списке вспомогательных компонентов с `isLoadedMod: false` и в число модов не входят; `isLibrary` определяет раздел списка, а не участие в счётчике. При следующем запуске новый проверенный архив библиотеки обновляет состав и число вместе; офлайн остаётся последний проверенный счётчик.

Для сборок со сложным выбором вложенных зависимостей `library/loaded-mods.json` хранит фактические ID и версии из реального ModList загрузчика, вместе с SHA256 каждого исходного JAR. Генератор отклоняет снимок после изменения состава или хеша JAR. Так варианты JarJar, которые загрузчик не выбрал, не попадают в итоговый счётчик. Платформенные записи Minecraft и Forge учитываются отдельно от состава модпака.

Для нативной сборки `library/content.json` задаёт `nativeProject` с именем проекта, игровой версией, полным Git-коммитом upstream и официальным HTTPS-адресом в полях `name`, `version`, `revision` и `websiteUrl`. Карточка показывает имя и версию движка рядом с версией Minecraft и сокращённым коммитом. Ссылка открывается на странице сборки.

Дескриптор нативной поставки имеет `schemaVersion: 2` и задаёт `nativeRuntime` с точной версией, платформой `windows-x64`, адаптером `portable-native` и исполняемым файлом внутри `native/`. Манифест требует `native-runtime-v1`, `native-steam-v1` и `minecraft-26-world-layout-v1`. Лаунчер проверяет поставку и запускает её EXE с аргументом `--game-dir`, путями переносимого кеша и данными Steam-профиля. Подготовка ресурсов, рабочее окружение, настройки игрового окна и запуск клиента принадлежат сборке.

У нативной сборки обязателен снимок `library/loaded-mods.json` со `schemaVersion: 1`, точными `minecraftVersion` и `nativeRuntime` из дескриптора, картой SHA256 всех файлов `native/` в `nativeFiles` и реально загруженными `mods`. У мода записываются `id`, `name`, `version` и `source`, путь к проверенному файлу из `nativeFiles`. Движок и общий Steam-транспорт в этот список не входят. Если загруженных игровых модов нет, публикуется пустой список и в деталях карточки скрывается раздел модов.

Генератор игрового манифеста вызывает `stage_library`, кладёт детерминированный архив `library-<sha256>.zip` в `dist/assets` и добавляет необязательный отдельный объект `library` к `pack-manifest.json`. Архив содержит только `library.json` и `preview.jpg`. Он не входит в установочные `assets` и не копируется в игровые папки. Старые лаунчеры игнорируют новое поле. Действующий workflow публикует все payload до манифеста и сохраняет этот порядок.

`python -m unittest discover -s tools -p test_pack_library.py` проверяет генератор. В каждом репозитории `generate_manifest.py --verify-only` проверяет также размер, SHA-256 и ревизию архива библиотеки.

## Пересоздание опубликованной сборки и переход старых установок

Манифест описывает весь активный управляемый состав. Лаунчер сверяет фактические размер и SHA256 локальных файлов перед повторным использованием; прежняя ревизия, имя файла и время записи не заменяют проверку. Загрузка и проверка staging заканчиваются до применения. Маркер `.portable-pack-apply.json` сохраняется при прерванном применении и запрещает офлайн-запуск до успешной повторной синхронизации. Синхронизация и подготовка экземпляра отклоняются, пока для сборки существует живой процесс игры.

Старые файлы распознаются по `.portable-pack-sync.json`, `.portable-instance.json` и необязательному `legacyFiles` манифеста. `legacyFiles` содержит только подтверждённые исторические `{path,sizeBytes,sha256}`; это не active files и не повод удалять личные данные. Исторические хеши сохраняются в `retiredFiles` локального состояния, чтобы очистить также старый экземпляр без полной instance-метки. В таком экземпляре удаляются только совпавшие исторические размер и хеш. Неизвестные исходные файлы сохраняются на диске и не входят в активный состав проверенного экземпляра.

Файл `launcher/pack-owned.txt` явно задаёт управляемые конфиги, скрипты и ресурсы. Его ownership сохраняется в состоянии экземпляра, поэтому снятие пути вместе с claim убирает старый управляемый файл. Изменённая локальная копия предварительно сохраняется в `Personal/PackConflicts`; ошибка сохранения прерывает замену. Неизвестные или изменённые JAR экземпляра также сохраняются там перед исключением из активной папки `mods`. Личные `options.txt`, миры, playerdata и скриншоты не становятся собственностью сборки. Такие правила обеспечивают переход установки, но не обещают совместимость старых миров после изменения registry ID.

Проверка перехода выполняется в отдельной технической копии через `tools/PackMigrationQa`. Она использует производственные службы синхронизации, контролируемый обрыв и повторную попытку, считает повторно загруженные байты и проверяет личные тестовые файлы. Личные игровые экземпляры и миры стендом не являются.

Приложение кеширует индекс, игровые манифесты и проверенные превью в `Minecraft/Launcher/Library`. Стартовый проход ограничен 15 секундами и четырьмя загрузками одновременно. Далее переходы, выбор сборки и запуск игры не запрашивают новые манифесты: скачиваются только файлы зафиксированной версии. При удалении старого payload с GitHub нужно перезапустить лаунчер. Недоступность сети сохраняет последний исправный кеш и установленные сборки.

## Локальный AI в загрузке сборки

`launcher/local-ai.json` связывает мод по пути и SHA256 с закреплённым рецептом под `launcher/`. Рецепт принадлежит сборке: в нём находятся версия, HTTPS-адрес, размер и SHA256 runtime, путь установки внутри переносимого Java home, registry origin и точный model manifest. Лаунчер не выбирает запасную модель или версию.

Перед большим скачиванием `PrepareDownloadPlanAsync` фиксирует тот же проверенный манифест сессии и получает из небольших проверенных assets отдельный снимок `launcher/*`, в том числе при первой установке. Лимит метаданных и их assets — 8 МиБ. Снимок не переписывает установленную сборку; загруженные assets повторно используются при применении. Изменение локального управляемого состава после планирования прерывает операцию до применения и требует повторить запуск.

Размер оставшихся файлов сборки, архива AI и всех config/layer blobs модели резервируется до первого большого payload. Они используют общий прогресс «Сборка». Проверенный кеш не требует повторной загрузки; докачка и повторная попытка учитываются в пределах того же объёма. Последующая подготовка runtime и проверка экземпляра сохраняются. При безопасном откате к локальной сборке AI-рецепт также повторно выбирается из её файлов, а не из неустановленного обновления.

Рекомендация RAM для ещё не установленной сборки читает её `reserveMemoryMb` из такого же проверенного снимка и проверяет рецепт и SHA256 привязанного мода по манифесту. Для этого доступны только небольшие assets с `launcher/*`; JAR, runtime и blobs не скачиваются, игровые папки не создаются. Ошибка метаданных оставляет оценку неизвестной. Обычная сборка без AI использует прежнюю оценку из манифеста без дополнительных запросов.

Необязательный `model.blobUrls` задаёт HTTPS-адрес для каждого SHA256 из закреплённого model manifest, включая config. Набор ключей должен точно совпадать с полным набором digest без `sha256:`; размеры и проверка хешей по-прежнему берутся из manifest. Все адреса входят в `recipeSha256`. Такой выпуск сборки объявляет `local-ai-blob-urls-v1` в `requiredLauncherFeatures`, чтобы старый EXE отказался до загрузки. Рецепты без `blobUrls` сохраняют прежнее получение blobs через свой `registryUrl`; дескриптор без закреплённого рецепта остаётся только источником RAM-метаданных и не включает скрытый рецепт из лаунчера.

Кеш хранится внутри `Minecraft/Launcher/LocalAI`, runtime — под переносимым Java home. Подготовка файлов не запускает backend и не переписывает игровые конфиги: запуск и завершение AI принадлежат моду сборки. Общий технический стенд описан в `tools/ForgeRuntimeQa/README.md`, а сценарий и QA-контракт принадлежат репозиторию сборки; маленькие сетевые fixtures не подтверждают ответ реальной модели или игровой жизненный цикл.

## Встроенный снимок каталога

`Program/LibrarySeed` содержит встроенные описания и превью на случай первого запуска без интернета. Это интерфейсный резерв, не установочные файлы Minecraft. После `git fetch` и проверки актуальности рабочих копий сборок снимки пересобираются из текущих jar командой:

```powershell
python tools/build_library_seeds.py --packs-root C:\путь\к\Packs
```

Скрипт берёт стабильные папки и ID из `tools/pack-catalog.json`, ревизию из Git каждой сборки, проверяет все архивы до записи в `Program/LibrarySeed`. Дескрипторы и промежуточные архивы сохраняются в `artifacts/library-seeds`. Параметры `--output` и `--staging` позволяют проверить генерацию без замены встроенного каталога. Абсолютный путь к исходным сборкам используется только этим инструментом подготовки; приложение от него не зависит.

`Program/Resources/pack-display-names.json` не редактируется как отдельный список названий: `python tools/build_display_name_snapshot.py` извлекает его из `library.json` встроенных архивов. `--verified-cache путь` дополнительно принимает опубликованный архив из кеша лаунчера, проверяя SHA256, размер, ревизию и ID/путь по сохранённому манифесту; в снимке остаются ревизия и SHA256 источника. Так включено уже опубликованное имя Modified из ревизии `f180e69d8e2fc01849c43e8ce2298ef27e2413cb`. Снимок только уточняет регистр совпавшего локального имени, не возвращает удалённые карточки и не заменяет свежие проверенные названия. Чтение этого небольшого ресурса не загружает превью или деревья модов; заголовок уже запущенной игры сохраняет имя, выбранное при её запуске.

## Удалённые сборки

LL8 Extended снята с публикации: её нет в индексе GitHub, встроенных карточках и начальном выборе. Старые кеши и source-маркеры не возвращают публичную карточку. При наличии установленной локальной копии она доступна в списке запуска как локальная сборка; её файлы и миры сохраняются. Для нового профиля начальная сборка — All The Mods 10.

Без подтверждённого индекса GitHub текущего запуска библиотека показывает только сборки из личного списка «Добавить», используя кеш или встроенное описание. Успешная проверка индекса при запуске открывает весь проверенный каталог, включая новые GitHub-сборки, отсутствовавшие в EXE. Их описания сохраняются в кеше; без сети карточка видна после добавления в личный список. Просмотр и изменение личного списка не запускают новые сетевые проверки.

Выпуск 410 однократно снимает принудительное скрытие локальной LL8 из старых настроек при наличии её установки в `Minecraft/Packs`. Метка `ll8LocalVisibilityMigrated` не меняет общую версию схемы и предотвращает повторный сброс последующего ручного выбора «Убрать из списка». Новые настройки и `Save` закрывают миграцию без изменения намеренного скрытия. Публичный каталог и синхронизация с удалённым репозиторием LL8 остаются отключены.
