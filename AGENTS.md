# Правила работы над лаунчером

## Интерфейс

- Дизайн-система — `DESIGN.md`; токены — `Program/App.xaml`, `Application.Resources`, одним плоским списком (без merged dictionaries: тесты грузят разметку loosely и вклеивают ресурсы по имени).
- В разметке нет hex-цветов, `SystemColors` и своих чисел для размеров, отступов и шрифтов — только токены (`Brush.*`, `Font.*`, `Space.*`/`Gap.*`/`Pad.*`, `Size.*`, `Radius.*`). Нужно новое значение — сначала токен и строка в `DESIGN.md`, потом использование.
- Отступы только из шкалы 4 / 8 / 12 / 16 / 24. Один акцент на экране. Прозрачность для выключенных не используем.
- Тесты `DesignTokensTests` держат `App.xaml` и `DESIGN.md` в одном составе и не пускают цвета в разметку.
- Окно свободно меняет размеры, сохраняет системную рамку и Windows Snap. `RootGrid` без `Viewbox`, основные столбцы всегда 2:1 с промежутком 24 DIP; настройки состоят из трёх строк под колонками «Играть»/«Библиотека» 3:2 с промежутком 8 DIP. После изменения размеров, отступов или шрифтов прогнать `WindowCanvasTests` и перемерить окно настоящими контролами через net10-консоль `tools/MeasureLayout` (команды в `Program.Tests/TESTING.md`); офлайн-рендер PowerShell 5.1 подменяет `CenteredDropDown` и ошибается по высоте.
- Шрифт системный `Segoe UI Variable Text, Segoe UI`; тесты используют те же установленные шрифты без подмены на Montserrat или файловый URI.
- Обработчики в `MainWindow.xaml` — только из списка, который вырезает `WindowCanvasTests.LoadWindow` (`Click|Loaded|Closing|SelectionChanged|TextChanged|PreviewTextInput|LostFocus|KeyDown|DataObject.Pasting`); новый тип обработчика — сначала в этот список.
- Имена элементов, `Content` кнопок и позиции строк/колонок пинят тесты `PeerDiagnosticUiAndDiscoveryTests` — менять вместе с ними.
- Системные `MessageBox` вне темы; свои диалоги (`WorldTransferConfirmationDialog`) наследуют стили из `App.xaml`.

## Релизы

- Номер релиза = число коммитов в `main`; перед коммитом добавить `## <N+1>` в `Program/Changelog.md` — одна версия, один абзац, без длинного тире.
- Описание версии — ровно два коротких предложения, не длиннее 240 символов вместе. Это окно «Что нового», а не отчёт: берутся два самых заметных для игрока изменения, остальное остаётся в коммите. Держит `ChangelogTests`.
- Перед коммитом прогнать `.\Program.Tests\Test-Launcher.ps1 -Profile Release` (компактный обязательный профиль с проверкой TRX, без пропущенных случаев). Полный набор необязателен для каждого выпуска: `-Profile Full`; матрица адаптеров: `-Profile Adapters`. Состав профилей и правила запуска — `Program.Tests/TESTING.md`. Для сборки java-адаптера задать `JAVA_HOME=C:\Tools\jdk-25.0.2`: в `PATH` только стубы Oracle (`java`, `javac`), `jar.exe` там нет, и без `JAVA_HOME` сборка падает на `jar.exe was not found`. Без JDK — `-SkipPortableIdentityAdapter`, состав тестов тот же.
- Префлайт по настоящим jar'ам гонится локально: `Program/IdentityAdapters/Common/Verify-IdentityAdapter.ps1`. Он повторяет то, что лаунчер вывел в прошлый запуск сборки, поэтому после правки `IdentityAdapterMappingService` сборку надо один раз запустить, иначе проверятся старые алиасы.
- После завершения правок и обязательных проверок сразу отправлять новую версию в GitHub. Действующие инструкции хранить в `AGENTS.md`, `DESIGN.md`, `Program.Tests/TESTING.md` и документации инструментов; воспроизводимые стенды — в `tools`, временные результаты и сборки — в игнорируемой папке `artifacts` внутри репозитория.

## Страницы модов в библиотеке

- Название каждого мода, его аддона и вспомогательной библиотеки открывает официальную страницу проекта с описанием и загрузками в системном браузере. Кнопка стрелки отдельно раскрывает аддоны; нажатие на ссылку не меняет раскрытие.
- Приоритет источников: CurseForge, если у этого самого проекта там нет страницы — Modrinth, затем официальный сайт или репозиторий автора. Проверять автора, актуальный jar/хеш и принадлежность форка; не подставлять одноимённый чужой проект, поисковую выдачу, зеркало, прямой jar или страницу жалоб.
- Проверенные HTTPS-ссылки по стабильным mod ID хранятся в `library/mod-pages.json` каждой сборки и попадают в `websiteUrl` метаданных. Генератор отклоняет новый мод без ссылки. При обновлении jar или добавлении сборки актуализировать и проверять ссылки до публикации; ключи API не коммитить и не выводить.
- Если встроенный компонент существует только внутри исходной авторской сборки и не имеет самостоятельной страницы, использовать официальный источник этой сборки и явно документировать такое исключение. Не выдавать страницу другого мода за отсутствующую.
- Поиск страниц делается при подготовке каталога, а не в работающем лаунчере. Открытие страницы не выполняет проверку обновлений, установку или переключение сборки. Старый дисковый кеш без `websiteUrl` использует ссылки встроенного каталога.

- Недоступный авторский адрес помечать объектом `{ "url": "https://…", "available": false }` в `library/mod-pages.json`. Название такого мода отображается обычным некликабельным текстом, без подсветки ссылки; последнее подтверждённое происхождение сохраняется для будущего восстановления.

## Подготовка и проверка производных модпаков

- Перед изменением фиксировать точные версии платформы, состав и SHA256 исходных JAR/конфигов/скриптов. Работать в отдельной независимой копии, проверенной по этому снимку; исходный игровой экземпляр не использовать как стенд и не откатывать чужие параллельные изменения документации/инструментов. Мир копировать только после согласованного сохранения и штатной остановки; fixture-архив не выдавать за бэкап личного мира.
- Производная сборка не считается «только аддонами», если заменён хотя бы один базовый JAR или изменён существующий скрипт/ресурс. Каждую такую замену явно документировать: старые/новые версии, SHA256, причина и последствия для старых registry ID. Зависимость, впервые добавленная в производную сборку, не становится базовым модом при её последующем обновлении. Никаких скрытых массовых обновлений общих библиотек. Отдельно раскрывать helper-инъекции в базовые моды: прежний SHA авторского JAR не означает прежнее runtime-поведение.
- Рано выполнять общий запуск согласованного клиента и dedicated server и вход в копию мира. Делать это до больших вложений в управление, защитные framework и индивидуальные сценарии, затем повторять после существенных изменений. TOML/ranges, наличие символов и офлайн Mixin не доказывают runtime-совместимость; shared Redirect нужно проверять на фактическом target/invoke. Наличие или отсутствие NoRefMap само по себе не объясняет конфликт. Для пользовательского LAN через лаунчер любой участник может быть хостом встроенного сервера; private dedicated остаётся вспомогательным QA, а не назначенной пользователю производственной ролью.
- Последнее явное решение пользователя определяет приёмку. Для Modified согласованы стабильный полный запуск/мир/анализ логов без новых критических сбоев, с явным отчётом оставшихся ERROR; CUA, физический ввод, отдельные способности, два клиента и визуальная оценка не обязательны. Не навязывать их заново как блокеры и не помечать непроведённые проверки PASS. Успешный серверный Done или нативный packer отдельно не являются PASS полного клиента. Новое конкретное требование пользователя, например обычный выбранный скин для себя/пира и исправление первого лица при сохранении превращений, фиксировать отдельно: общий отказ от CUA не отменяет его и не разрешает объявлять визуальную проверку двух клиентов выполненной.
- У каждого собственного Forge JAR проверять корректный pack.mcmeta, версии и стороны загрузки. Для Minecraft 1.20.1 используется format 15; разбор проверять настоящим Minecraft serializer, а точечные mixin/reflection исправления привязывать к конкретному caller/site и SHA исходного JAR. Не маскировать ошибку отключением обязательной инъекции, заменой custom-механики ванильной или подавлением логов.
- GPU atlas проверять на раннем полном клиенте: снять фактический предел GPU и геометрию sprites, затем проверить родной Stitcher и реально используемый backend. Площадь ниже предела сама по себе не доказывает укладку. Atlas budget, shader link и depth/stencil format совместимость framebuffer — разные проверки; успешный Stitcher не исправляет несовместимый depth blit. Стек GL debug callback без доказанного synchronous режима не устанавливает происхождение всех ошибок и stalls. Строку Sprites в мегабайты не печатать целиком: потоково разобрать в небольшой отчёт или ограничить вывод, например rg --max-columns 600 --max-columns-preview.
- Не отключать молча эффекты, шейдеры, анимации, проверки зависимостей и native format guards ради запуска. Любое допустимое упрощение качества явно назвать и ограничить точным набором ресурсов; различать decoded atlas-копию и оригинальные PNG/direct GUI/VFX. Сохранение исходных файлов не означает отсутствие изменения отображаемого качества.
- Сопоставлять логи по точным ошибкам/ID и временному окну, разделяя baseline, введённые изменения и известные нефатальные остатки. Не называть все ERROR унаследованными только потому, что игра продолжила запуск. Предупреждения о потерянных registry ID после обновлений не позволяют обещать перенос старых миров без потерь. Публично не публиковать личные пути, пароли и необработанные пользовательские логи.
- Итоговый состав и активные lock-записи изменяет один назначенный владелец последовательно: exact-hash замена, список активных файлов, соответствие реальным JAR/mod ID, затем библиотека и публикационные locks. Исторические исключения хранить отдельно от active files, если старые потребители не понимают included:false. Новая карточка библиотеки сама по себе не требует выпуска EXE лаунчера. При удалении мода также сверять строгие gamerule/скриптовые ссылки, назначения клавиш и orphan-config; one-time метка в старом QA-мире может скрыть ошибку первого запуска нового мира.

При player-only terrain policy проверять claim до player exemption, включая существующие BE, а inventory clear/removal — до побочного эффекта. Не включать shared global destruction flag вокруг игрока. Player может быть victim/DOT, поэтому tick/Entity-аргумент без доказанной source-role не даёт caster permission; UNKNOWN остаётся консервативным. При политике только для новых модов фиксировать исходные BASE mod ID и исключать их даже после обновления JAR; новая зависимость остаётся NEW. BASE source проверять отдельно от BASE victim/receiver: чужая машина или жертва не снимает claim-защиту с NEW способности.
